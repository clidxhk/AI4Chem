# AGENTS.md — 手册编写规范

本文件是 `手册/` 子目录的专属说明，适用于在本目录下创建、修改讲义章节的所有协作者（包括 AI 编程助手）。仓库整体说明见根目录 `AGENTS.md`。

## 一、手册是做什么的

《AI for Chem 实用学习手册》是共学班的最终交付物：把 12 次讨论的录音转写、成员笔记和对比分析，逐步整理成结构清晰、面向化学研究者的入门讲义。

每次讨论对应整理为一个部分。

## 二、章节文件组织

- **文件命名**：`第<N>部分-<主题>-<版本>.md`，如 `第一部分-AI-for-Chem的第一次讨论-通用版.md`；
- 每个部分维护**两个版本**：
  - **课程版**（`*-课程版.md`）：保留课题组内部背景与成员发言语境，供组内使用；
  - **通用版**（`*-通用版.md`）：弱化具体课题组背景、成员发言匿名化、口语适度书面化（不改变原意），适合对外发布；
- 两版内容同源：课程版先行整理，通用版在其基础上匿名化改写；
- 配图如需要，存放于本章同目录下的 `图片/` 子目录。

## 三、编写规范

1. **匿名化**：通用版中涉及个人身份的信息一律匿名处理；引文需注明为匿名摘录；
2. **忠实原意**：整理转写内容时可修正口语和转写错误、调整结构，但不得改变发言者的原意；
3. **章节结构**：开篇说明本章来源与整理方式（引言块），正文按问题/主题分节编号（如 1.1、1.1.1），结尾可附讨论沉淀的共识或待探讨问题（具体结构与文风规范见第四节）；
4. **写作语言**：正文使用中文；专业术语、工具名保留英文原文；
5. **格式**：Markdown；
6. **原始材料不动**：录音转写、成员笔记等一手材料存放在各次活动目录，本目录只存放整理成果，不修改原始材料。

## 四、结构与文风规范

### 4.1 内容归位，不设"延伸"附录

- 自由讨论中的延伸问题与组内补充学习材料**不单独设章**，按主题并入正文对应小节；
- 趣闻故事类内容**织入正文中最相关的位置**，作为叙事的一部分，不作为花边附录；
- 同一知识点在发言记录与补充材料中重复出现时，只讲一遍；
- 新增内容若有值得进小结的结论，并入本章小结，不为它单独开小节。

### 4.2 通用版文风

- 面向读者写作，用讲义口吻，避免"会议纪要感"：不使用指向具体小节编号的内部交叉引用（如"对应 X.X 的问题"），少用纯罗列，多用衔接性散文；
- 引文统一标注"匿名摘录"；**观点对比处按发言顺序用匿名编号（A、B、C……）标注各成员立场**；
- 匿名不等于磨平差异：区分"共识"与"个人独有见解"，独有见解必须保留——课程版署名，通用版用匿名编号。

### 4.3 整理原则

- 转写错误可修正，但不得改变发言者原意；查证类或有争议的表述标注不确定性，不写成定论；
- 成员提出的新见解与关于 AI for Chem 发展方向的讨论，是重点保留对象；
- 讨论中形成的方向性判断记入"待探讨问题"；**整理下一部分前，先检查上一部分的待探讨问题是否被接上**，保持跨章节线索；
- 课程版中记录的"会后安排"须与会后实际情况对齐，过时处加注说明；
- 引言块保留"AI 参与说明"与状态标注，供成员核对修订。

## 五、与 AI 助手的协作流程

- 章节初稿由 AI 助手通读该次全部一手材料后起草；初稿完成后，组织者会通读并给出方向性反馈（文风、结构类），AI 据此做**整体迭代**，而非零碎修补；
- **组织者可能直接手动编辑手册文件**：AI 覆盖写入前必须先重新读取目标文件、比对差异，保留组织者的手动改动；
- 重排与润色不得丢失事实与数据；
- 每轮修改后按 Git 规范提交并推送，提交信息说明本轮改了什么、为什么。

## 六、Git 工作流（强制）

遵循仓库根目录 `AGENTS.md` 的 Git 强制要求：**每次修改后必须 `git add` → 中文提交信息 `git commit` → `git push origin master`**，不允许改动长时间留在本地。

# 第二次讨论：计算机的本质——从发展史、硬件到”理解化学”

# 引言

开始学习 AI 之前，值得先停下来问一个更基础的问题：**计算机到底是什么？**

它和锤子、烧瓶这些工具有什么本质不同？为什么训练神经网络要用 GPU 而不是 CPU？为什么你让 AI”把这组光谱处理一下”，它给不出想要的结果？

本章围绕五个问题展开：

1. **发展历史**：从巴贝奇、阿达·洛芙莱斯到图灵、香农、冯·诺伊曼、霍珀、汤普森和里奇，这些人分别做了什么？
2. **硬件**：计算机至少需要哪些硬件？GPU 和 CPU 的区别是什么？为什么 GPU 适合 AI 训练？
3. **编程语言**：为什么不能直接用自然语言告诉计算机？为什么有这么多编程语言？
4. **操作系统**：为什么计算机需要操作系统？Windows 和 Linux 的区别是什么？为什么一段代码在这台电脑能运行，换一台就不行？
5. **本质**：计算机与普通工具最大的区别是什么？它到底是在”理解”，还是在”处理”？它真的”理解”化学吗？

## 2.1 计算机的早期发展历史

### 2.1.1 七位时代的代表人物，各自解决了什么问题

计算机并不是某个人”发明”的。

它在两百年间，经历了6个发展阶段：

> 机械计算 → 电子计算 → 晶体管与集成电路 → 微处理器与个人电脑 → 网络与云计算 → 大规模并行计算与 AI
> 

这条两百年的路上，有7个名字在早期历史上刻下了自己的印迹：

| 人物 | 年代 | 做了什么 | 一句话贡献 |
| --- | --- | --- | --- |
| 巴贝奇 Charles Babbage | 19 世纪 30 年代 | 设计差分机与分析机 | 第一次给出”通用可编程机器”的机械蓝图：分析机已有存储器与运算器之分，用穿孔卡片输入 |
| 阿达·洛芙莱斯 Ada Lovelace | 1843 | 为分析机写下计算伯努利数的算法 | 世界上第一位程序员；最早意识到机器能处理的不只是数字，而是任何可用符号表达的信息 |
| 图灵 Alan Turing | 1936 | 提出图灵机模型 | 从数学上定义”可计算”，并证明存在通用机器——一台机器可以模拟任何其他机器；另提出图灵测试，二战期间参与破译 Enigma 密码 |
| 冯·诺伊曼 John von Neumann | 1945 | EDVAC 报告 | 提出存储程序结构：指令与数据同存于内存，机器由运算器、控制器、存储器、输入、输出五部分构成 |
| 香农 Claude Shannon | 1937 / 1948 | 开关电路的布尔代数分析；信息论 | 证明可以用继电器的开关直接实现逻辑运算，把逻辑变成电路；后创立信息论，定义信息的最小单位 bit |
| 霍珀 Grace Hopper | 20 世纪 50 年代 | A-0 编译器，推动 COBOL | 主张”程序应该用接近人类语言的方式写”，并做出了世界上最早的（批）编译器之一，把程序员从机器码中解放出来；“Bug/Debug”一词的流行与她有关 |
| 汤普森与里奇 Thompson & Ritchie | 1969–1973 | 创造 Unix 与 C 语言 | 用高级语言 C 重写操作系统内核，使系统第一次可移植；Unix 的血脉延续到 Linux、macOS、Android |

历史局限：分析机当时并未完整建成；冯·诺伊曼架构是多人共同发展的成果；图灵的工作同时也揭示了计算的边界——有些问题在数学上就是不可解的。

**注意：真实的计算机史是连续的集体工程，不是一人一项发明的接力。**

> **第一个Bug**
1947 年 9 月 9 日，哈佛大学的 Mark II 计算机突然失灵，霍珀排查后发现，一只飞蛾卡在了继电器里，导致电路断开。他们把飞蛾用胶带贴在运维日志上，写下”First actual case of bug being found”（发现 bug 的第一个实例）。需要澄清的是，“bug”一词早在此之前就被工程师用来指称故障，爱迪生的笔记里也出现过——这只飞蛾不是词源，却是这个词流传至今的图腾。今天我们说”程序有 bug”，源头就是那只倒霉的飞蛾。
>

## 2.2 硬件：计算机靠什么工作

### 2.2.1 一台计算机至少需要什么

按冯·诺伊曼结构，缺一不可的是五样东西：

- **运算器**——执行加减与逻辑判断；
- **控制器**——决定”下一条指令是什么”（两者合起来就是 CPU）；
- **存储器**——内存（RAM，断电即失）加外存（硬盘/固态，长期保存）；
- **输入设备**——键盘、鼠标、网卡……
- **输出设备**——屏幕、网卡、打印机……

外加把它们连起来的主板/总线和供电。

一句话概括：**能算、能记、能进、能出、能按顺序执行**。

### 2.2.2 CPU 与 GPU：两种不同的芯片

| 维度 | CPU | GPU |
| --- | --- | --- |
| 核心数量 | 几核到几十核 | 数千到上万个简单小核心 |
| 核心设计 | 复杂：分支预测、乱序执行、大缓存 | 简单：众核同构，控制单元少 |
| 擅长 | 低延迟、逻辑复杂、分支多的**串行**任务 | 高吞吐、规则、可并行的**批量**计算 |
| 比喻 | 几个资深博士，能处理棘手问题 | 几千个小学生，同时做同一道算术题 |
- CPU 是通用计算，什么任务都能干，但面对大规模简单运算就慢；
- GPU 不擅长复杂逻辑分支，但擅长大量简单、重复的运算。

3D 游戏画面由一个个三角形组成，画线时只存两个顶点坐标，中间的点全靠简单乘加实时算出来；CPU 只能一个点一个点算，于是人们干脆造出一堆只会算乘加的计算单元，让控制器负责装填数据、所有单元同时开工——这就是 GPU，**单指令多数据**。

反过来，传统 GPU 无法执行跳转指令：遇到 if 分支，它要把两个分支都算完再挑一个赋值；层层依赖的代码更是没法并行。

CPU 核心里有很大一块电路专门做**分支预测**，伺候复杂逻辑；GPU 则不停堆叠计算核心——十年前的 GTX 980 就有 2048 个 CUDA 核心。

**注意：CPU 也能并行计算；GPU 并非在所有任务上都更快**。

### 2.2.3 为什么 GPU 适合 AI 训练

一句话：**AI 训练的本质是海量矩阵运算**——数以亿计的、彼此独立的乘加。这类任务有三个特点，恰好与 GPU 的长处对齐：

1. **高度并行**：同一批数据跑同一个运算，几千个核心可以同时干活；
2. **对延迟不敏感**：吞吐量远比”单次响应有多快”重要；
3. **精度可压缩**：训练可以用 FP16、BF16 甚至 FP8 低精度格式；现代 GPU 内置 Tensor Core 等专用矩阵单元，专攻低精度张量运算。

再加上 HBM 高带宽显存能持续把数据喂给计算单元（HBM3 可达上 TB/s，而传统 CPU 内存通常只有几十到上百 GB/s），GPU 在 AI 训练上比 CPU 快出几个数量级。

**注意：GPU 负责加速计算，CPU 仍负责组织任务，两者是配合关系，不是替代关系。**

### 2.2.4 延伸：NPU 是什么

除了 CPU 和 GPU，现在还常听到第三种处理器：**NPU（神经网络处理器）**。

它是一种更专一的 AI 芯片，只服务于神经网络计算，功耗更低、体积更小。

它的来龙去脉是这样的：AI 的核心是矩阵运算，2017 年起英伟达在显卡中加入专门做矩阵计算的 Tensor Core，形成”RT Core（光线追踪）+ CUDA 核心（图形与通用计算）+ Tensor Core（神经网络加速）“的 GPGPU 结构；

而 NPU 干脆把矩阵计算单元做进硬件里（如华为昇腾的 Cube Core 可直接对 16×16 的 FP16 矩阵做乘法），云、边、端都可以部署——谷歌 TPU、Meta MTIA 原理都类似。

### 2.2.5 算力是怎么算出来的

买显卡、租云服务器时都会看到一个指标：“多少 TFLOPS”。算力到底在算什么、又是怎么算出来的？

一般说的算力就是 GPU 的浮点运算能力，以**每秒浮点运算次数（FLOPS）**衡量。

TFLOPS 指每秒万亿次浮点运算，适合衡量 GPU 在科学计算/AI 训练上的能力；TOPS 指每秒万亿次操作（含整数、逻辑运算），更多用于 NPU 等专用 AI 芯片的低精度场景。

理论峰值算力有个简单的公式：**CUDA 核心数 × 加速频率 × 每核心单周期浮点计算系数**。

以 NVIDIA A100 为例：6912 个核心 × 1.41 GHz × 2 ≈ **19.5 TFLOPS**（FP32）。

但算力高不等于实际性能好。

**显存带宽**决定数据喂得多快（RTX 4090 约 1008 GB/s，A100 约 2039 GB/s），算法并行性、软件优化、功耗都影响实际表现——算力像汽车的马力，显存带宽像公路宽度，实际能跑多快还要看驾驶技术。

### 2.2.6 载体不止是电：光计算与非电子计算

计算机真正需要的只是两种可区分的“符号状态”（0/1），晶体管用通断把它落实为电路里的高/低电平；因此从原理上说，承载 0/1 的介质并不一定非得是电。

顺着这个思路，很多人尝试用光来做通信甚至计算（光子速度快、可并行），但目前光计算仍有一些硬约束：

- 早期光的控制很难；光有衍涉问题，全部用光做运算的处理器会非常大；
- 更关键的是**集成度**：晶体管可以做到纳米级，而光器件最小是微米级——集成不上去；
- 另一方面，半导体内电子移动速度较慢，晶体管小型化也接近极限，所以有人尝试把光和硅结合（硅光）。

我们还可以提出一个更开放的问题：

> 既然计算机所需要的是0 和 1 ，我们能不能用别的物质做计算？甚至 DNA 计算、细胞计算？
>

## 2.3 编程语言

### 2.3.1 为什么不能直接用自然语言

1. **计算机底层只认 0 和 1**。CPU 只能识别高低电平代表的二进制机器码，需要明确、无歧义、步骤精确的指令；从自然语言到电路动作之间，缺少一条确定性的转换规则，需要编译器/解释器来翻译。
2. **自然语言充满歧义**。“稍微放大一点”——“一点”是多少？“把它放在桌上那个盒子里”——是盒子在桌上，还是东西要放到桌上的盒子里？自然语言的强大来自共享的理解与容错，而这正是机器没有的。

**注意：**大模型并不是直接执行”人话”。它先把自然语言**词元化**，对内容做**概率预测生成代码**，代码再转换为机器码执行——“听懂人话”的表象下面，仍是层层翻译。

### 2.3.2 指令集与汇编：从 0/1 到”人话”的第一步

那”层层翻译”的第一层是怎么搭起来的？

硬件能执行的操作就那几项，底层为它写一个**指令集**，规定它要做哪些操作（比如输入、输出）；

汇编语言把这些 01 序列变成”动作”，更高层的语言则在汇编之上操作。

这样，“打一段循环”“输出一段音频”就可以在人能读懂的层面完成。

换个角度理解：

硬件能进行的操作，其实都已经”写到硬件里面”了——我们只是用更接近人的语言转化成机器码告诉它，它就输出相应的动作。

从机器码到汇编语言，再到高级语言，每一层都在把”控制硬件”这件事做得离人更近一步；

### 2.3.3 为什么有这么多编程语言

因为不同场景需要不同的权衡：

| 取舍维度 | 举例 |
| --- | --- |
| 性能 vs 开发效率 | C/C++ 贴近硬件、极致性能；Python 写得快、生态强，是 AI 与数据分析首选 |
| 运行环境 | JavaScript 活在浏览器里；SQL 活在数据库里 |
| 企业级应用 | Java 稳定、跨平台；Go 为高并发微服务而生 |
| 内存安全 vs 控制力 | Rust 用所有权换安全；C 把刀交给你，也把风险交给你 |
| 历史与生态 | 银行系统的 COBOL 还在跑，重写成本高于忍受 |

## 2.4 操作系统

### 2.4.1 为什么需要操作系统

一个常用的比喻：

操作系统是**管家**——硬件只能听懂最基础的硬件语言，真正让它们协同工作的是操作系统。

想象一下没有管家的样子：每个程序都要自己写硬盘驱动、自己管理内存、自己决定谁先用 CPU，那么同一台机器上的两个程序会互相踩踏内存，换一块网卡就得重写所有程序，多任务根本无法实现。

归结起来，操作系统的职能是三点：

1. **硬件抽象与统一接口**：把复杂的物理硬件抽象成统一的 API（读文件、画窗口），程序不用直接操控硬件；
2. **资源调度与管理**：决定哪个程序优先用 CPU、如何安全分配内存、防止程序崩溃拖垮整机，让多个程序”同时”运行；
3. **提供用户交互界面**：命令行（CLI）或图形界面（GUI）。

**注意：简单嵌入式程序也可以不使用完整操作系统。**

### 2.4.2 Windows 与 Linux 的区别

| 维度 | Windows | Linux |
| --- | --- | --- |
| 内核与授权 | NT 内核，闭源商业授权 | 开源（GPL），可自由修改分发 |
| 主导场景 | 桌面办公、游戏、企业 IT | 服务器、云计算、超算、嵌入式 |
| 软件分发 | 安装包 / 应用商店 | 包管理器与软件仓库（apt、dnf、pacman） |
| 文件系统 | 盘符管理（C:、D:），路径不区分大小写 | 单一根目录，一切硬件都是文件，路径区分大小写 |
| 定制程度 | 有限 | 从内核到桌面环境几乎全部可换 |
| 交互方式 | 图形界面优先 | 命令行（Shell）优先，脚本化能力强 |

**Windows** 最大的优势是**兼容性**：大部分软件发布时会优先适配 Windows，游戏厂商也会主动适配；

而 **Linux** 往往需要使用者具备更多知识，自己搭运行环境。

也正因为开源，Linux 有大量发行版（Fedora、Arch Linux 等），更适合愿意投入知识去优化的高阶用户。

全球 TOP500 超级计算机几乎全部运行 Linux——可定制、可批量运维、无授权成本。

Linux”一切皆文件”的设计也值得一提：在 Linux 服务器上插一个 U 盘，它就被当作一个文件来管理。

> **Linux 的诞生**
1991 年，芬兰赫尔辛基大学 21 岁的学生 Linus Torvalds 买了一台 386 电脑。当时用于教学的 Minix 系统授权受限、功能也不趁手，他索性自己写了一个终端仿真程序来玩，逐步演进成了操作系统内核。同年 8 月 25 日，他在新闻组发帖，语气相当谦虚：“我在做一个（免费的）操作系统，只是个爱好，不会像 GNU 那样大而专业。”后来这个”爱好”与 Richard Stallman 发起的 GNU 项目结合，形成了今天的 GNU/Linux——一个想玩明白自己电脑的学生，最终改变了整个计算世界的基础设施。
> 

### 2.4.3 为什么一段代码换台电脑就跑不了

这是与科研复现关系最密切的一问。常见原因有五类：

1. **操作系统与可执行格式不同**：Windows 用 PE 格式（.exe）、调用 Win32 API；Linux 用 ELF 格式、调用 POSIX 系统调用，二进制互不识别；
2. **CPU 架构不同**：x86（常见 PC）与 ARM（常见便携设备、低功耗设备）指令集不一样；
3. **依赖库缺失或版本不符**：高版本库编出来的东西，拿到装着低版本库的机器上就报错，而且经常不告诉你为什么；
4. **语言运行时版本不同**：例如 Python 3.8 与 3.12 的行为差异；
5. **路径、环境变量、编码等环境假设不同**：代码里写死 `C:\...` 换台机器就报错；Windows 路径分隔符是 `\`，Linux 是 `/`；Windows 文件编码常见 GBK，Linux 常见 UTF-8，处理不好就乱码。

> **Ariane 5事故**
1996 年欧洲航天局 Ariane 5 火箭首飞，升空 37 秒后自毁，损失约 3.7 亿美元。原因不是新代码写错了，而是直接复用的 Ariane 4 旧代码在新火箭的飞行参数下，一个数值从 64 位浮点转 16 位整数时溢出，主备两套系统因运行相同代码同时崩溃。教训与”代码换台电脑跑不了”是同一个道理：**代码的正确性依附于它被写下来时的环境假设；环境变了，正确性就要重新证明。**
> 

**注意：要复现一个计算结果，应同时记录代码、数据和环境；虚拟环境/容器能减少差异，但不能消除所有硬件限制。**

### 2.4.4 学 AI 要装 Linux 吗？

一个常见顾虑：大多数公司用 Linux 做云计算和 AI 训练（“一切皆文件”、高度模块化和自动化），学 AI 是不是得先装 Linux？其实有三个可行选项：

1. 在 Windows 上装 **WSL**（Windows Subsystem for Linux）——本质上是在 Windows 里装一个虚拟机，把 Linux 塞进去，顺便解决”代码只能在 Linux 跑”的问题；
2. 用 SSH 工具远程连接**云服务器**——一台练手的云服务器很便宜，十几块钱就能租到；
3. 有条件的话使用实验室或课题组共享的服务器。

## 2.5 计算机的本质

### 2.5.1 与普通工具最大的区别

**最核心的答案是通用性/可编程性。**

普通工具的功能被物理形态所限制：锤子只能敲，锯子只能锯。

计算机不同——它可以存储和执行任意可描述的指令序列，换一套程序就变成另一种工具，功能由软件定义。

换个角度说，

- 普通工具是人体感官的延伸，比较具体；
- 计算机抽象、有逻辑性，能在没有人工干预的情况下根据中间结果自动做条件判断，连续完成成千上万步推理与迭代。

所以计算机不是”一种工具”，而是**制造工具的工具**——一台万能机器。

我们还需要注意更深的两个观察：

- **自指性**：计算机可以通过程序修改自己的运行逻辑。给它换一套指令，它就能干完全不同的工作——这让它比普通工具多了一点”自主性”。
- **层级抽象**：从电路信号 → 机器码 → 汇编 → 高级语言 → 自然语言交互，底层一旦确定，上一层就可以随意构建复杂逻辑。开源社区里那么多项目，底层的 CPU 都一样，做出来的事却千差万别——这种”底层确定、上层自由”的属性，是普通工具没有的。

### 2.5.2 “理解”还是”处理”？

关于计算机的本质，有一组经典的争论：

**统计计算 vs. 机器智能**。

支持“统计计算”的观点认为，计算机的本质是**按规则对符号进行语法操作**。

给定输入、给定规则，产生输出；整个过程中没有任何环节需要”知道这些符号是什么意思”。哪怕大模型的输出很像”懂”，也只是统计生成的文本，不是理解。

为了论证上述命题，有两个经典的直觉模型：

> **”中文房间”**
房间里一个不懂中文的人，照着规则手册把递进来的中文问题换成中文回答递出去——从外面看他像懂中文，房间里却没有任何人理解中文。今天的 AI，本质上就是这个房间的一个极大、极强的版本。
> 

还有一个帮助建立直觉的实验：

> **“香农游戏”**
1951 年，香农和他的妻子贝蒂（Betty）在客厅里玩了这个游戏。香农手里拿着一本小说，挑出一段话，但他不给妻子看。他只给出开头，比如：“`The cat sat on the ___`”。妻子必须逐个字母（或单词）去猜下一个是什么。如果妻子猜“`m`”（想猜 mat，垫子），香农说：“对！”；如果妻子猜“`z`”，香农说：“错，倒回去重猜”。
香农发现了一个惊人的事实：人类对自己的母语有着极强的“统计直觉”。哪怕不看后面的内容，我们也能根据语法、常识和上下文，极其精准地预测后面可能出现的字母或单词。
> 

语言学家乔姆斯基的批评更直接：

**这类模型像一只”数学的鹦鹉”——你发给它什么，它学一学、重复一下。**

然而，随着模型规模的扩大，单纯的“否定论”开始遭遇现实现象的挑战。

另外一些观点认为：AI 在功能和现象层面的表现，已经远远超出了人们对“统计工具”的传统认知。

AI 的确只是在玩“猜词游戏”，但科学家们低估了**完美预测下一个词所需要的知识量**。

为了把猜词游戏玩到极致，大模型被迫在由数字组成的神经网络中，**模拟并重构了人类世界的运行规律、常识和文化**。它对数字世界高维模式的处理能力，已经不是简单的“复述”或“拼接”，而是产生了一种无法被简单统计公式概括的复杂映射。

他们认为，当我们看到 AI 展现出这种超预期的复杂行为时，我们对“智能”的定义必须发生转变——从**“主体体验”**转向**“功能表现”。**

当数据量和算力突破临界点时，大模型表现出了超越单纯统计累加的**涌现能力（Emergent Abilities）**（如突然学会了推理、小语种翻译、甚至反思自己的错误）。这种现象在传统的统计工具中是绝无仅有的。

**如果**“理解”必须包含人类的肉体痛苦、主观意识和情感顿悟，那么大模型永远只是无意识的统计机器；

**但如果**从功能主义出发，只要机器能够在中高难度的任务中，展现出高度符合人类逻辑、常识和创造力的反馈，那么**机器智能就已经在统计的废墟之上降临了。**

**“理解还是处理”，最终取决于你怎么定义”理解”和”认知”。**

### 2.5.3 计算机真的”理解”化学吗？

“计算机理解化学吗”这一问，五个人的回答都偏向”不理解”，但理由各不相同，恰好排成了一个从直觉到方法论的梯度。

**A回答是不理解** 它不知道什么是分子、化学键，只是执行数学公式、存储分子数据、匹配数据库——是人类把化学知识编码成数据与算法交给计算机。

**B回答承认功能的强大** 像人一样认识世界，计算机确实做不到（“中文房间”）；但从功能上看，它确实能够解决过去实现不了的问题。

**C从使用体验出发** 让 AI 优化一个产率不高的反应，它给的建议经常是”大炮打蚊子”；但通过优化数据库和逻辑判断，可以让它”看起来真的理解了化学”。

**D认为表示化学 ≠ 理解化学。** AlphaFold 能预测蛋白质结构，却不懂那个结构为什么稳定；分子生成模型能给出漂亮的候选结构，能不能合成、有没有用，仍要靠化学家判断。

**E重视”怎么评价”。** 量化软件可以按物理模型求解，AI 可以预测性质、提出反应方案，但**会输出机理图，不代表机理已被证实**——评价 AI 应看证据、适用范围、预测与实验能否相符，而不是语言是否流畅。

### 2.5.5 AI 与 Gaussian：统计与解方程

化学研究者日常的另一类计算——Gaussian 等量化软件、分子动力学模拟——和 AI 是什么关系？两者的求解方式截然不同：

- **量子化学计算/分子动力学模拟**是有明确约束条件的”硬解”：DFT 约束在从氢原子解出来的薛定谔方程框架下，分子动力学依据牛顿力学；
- 人工智能则是统计：给它一个数据集，它学的是出现的概率——“相当于在做选择题时，三短一长，猜一个对的”。

两条路线也在靠近：用机器学习辅助 DFT 计算，是当前活跃的研究方向。

### 2.5.6 AI for Chem未来的方向

一些认为：Self-driving Lab（自动驾驶实验室）——机器人协同做实验——已经在发展，虽然工程问题很多；具身智能如果发展得好，可能只是改变现有工作的任务分配比例，把人从操作里解放出来；而物质学科真正的层次跃迁来自**观察维度的变化**——从看细胞到看原子。

另一些认为：生物领域当初面对海量 DNA/RNA 数据时催生出了生物信息学，如果未来化学材料数据爆炸式增长，化学也可能出现类似的数据驱动分支。

## 本章小结

1. **历史是一条连续的集体工程**：从巴贝奇的“可编程机器”蓝图，到图灵给出“可计算”的数学定义，再到香农把逻辑落到开关电路，冯·诺伊曼确立存储程序结构，霍珀推动编译与“说人话的语言”，汤普森与里奇用 C 与 Unix 把系统带向可移植与生态繁荣。
2. **硬件的核心是“算、记、进、出、控”**：运算器与控制器（CPU）执行指令，存储器保存数据，输入/输出与总线把系统连接起来；晶体管通过“导通/截止”把 0 和 1 变成可操控的物理状态。
3. **CPU vs GPU 的差别来自任务形态**：CPU 擅长低延迟、分支复杂的串行逻辑；GPU 以海量简单核心换高吞吐，适合大规模并行的乘加与矩阵运算，因此成为深度学习训练的主力；NPU 则进一步把矩阵计算做成更专用、更省电的硬件。
4. **语言与操作系统是“层层抽象”**：自然语言充满歧义，而计算机需要无歧义指令；编程语言与编译/解释把“意图”逐级翻译为机器能执行的指令序列。操作系统提供统一接口与资源调度，让软件不必直接操控硬件，并解释了“代码换台电脑跑不了”的常见根源（OS/架构/依赖/运行时/环境差异）。
5. **“理解”之争是一条评价尺度**：从“符号处理不等于理解”（中文房间）到“完美预测需要世界知识”（功能主义/涌现），关键不在措辞是否像人，而在任务证据、适用范围与可验证结果。对化学而言，AI 更像强大的统计与表示工具：可以预测、生成、加速筛选，但“会说机理”不等于“机理被证实”，最终仍需用实验与理论约束来评价。

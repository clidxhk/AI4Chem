## 引言

第三次讨论的主题是"数据和信息——AI 的燃料从哪里来？"。课前的核心问题是：**你的实验记录本，在计算机眼里是什么？**

第二次讨论弄清了计算机本身：它只会按规则处理 0 和 1，并不"理解"什么。顺着这个问题自然就到了第三次：波长、产率、谱图、分子结构……这些五花八门的科研数据是怎么变成 0 和 1 的？反过来，一堆 0 和 1 又怎么变成"信息"甚至"知识"？这也是机器学习的前置课——**数据是 AI 的燃料**。第一次讨论分析 AIE 分子库时埋下的伏笔（预测效果的上限由数据集质量决定）在这里正式接上。

课前的讲义五问是：

1. **概念**：什么是数据？什么是信息？它们是什么关系？（再想一步：什么算知识？）从自己的实验记录或文献里各找一个"数据"和"信息"的例子。
2. **表示**：数据的类型有哪些？计算机里只有 0 和 1，文字、数字、图片、分子结构分别是怎么被表示的？
3. **结构化与非结构化**：两者有什么区别？盘点你的科研数据：哪些是结构化的，哪些是非结构化的？
4. **标准**：什么样的数据才算"好数据"？数据"多"和"好"哪个更重要？
5. **开放性问题**：结合自己的领域说说：文献里的数据为什么经常"不好用"？机器要"学出规律"，所提供的数据至少需要什么条件？

## 3.1 概念：数据、信息与知识

### 3.1.1 数据是原始记录，信息是解释结果

五位成员的定义高度一致：**数据是对事物状态的原始记录**——数字、文字、符号、图像、声音，尚未被解释；**信息是数据被放入语境、经过整理和解释之后产生的产物**，能够消除不确定性、对接收者产生明确意义。杨涵的表述最凝练：数据是信息的载体和基础，信息是数据的加工结果；数据 raw、含义未明，信息有序、有价值。

香农的定义在多份笔记中同时出现：**信息是减少（消除）不确定性的量**。李冲的开场补上了这段历史：20 世纪初电报电话兴起，信息传播非常昂贵、按字收费——香农正是从这种工程需求出发给出了信息的定义（他 1948 年创立信息论时在贝尔实验室工作）。

迪力把两者的关系讲得最透：

> 数据是载体，信息是数据的解释结果，不是数据本身的属性。同一份数据在不同语境下给出不同的信息；**没有语境的数据就是噪声**。

他的类比：体温计显示"37.2"是数据，"这个人发烧了"是信息——差别不在数字，而在**参照系与解释**。

五人各自从实验记录或文献里找的"数据 → 信息"例子，恰好覆盖了化学、生物两条线：

| 成员 | 数据（原始记录） | 信息（解释结果） |
|---|---|---|
| 迪力（AIE 表征） | 不同水含量 fw 下的荧光光谱强度值（如 fw=90% 时 605 nm 处 I=1847 a.u.） | 该分子具有典型 AIE 特性：聚集后荧光增强约 XX 倍，发射峰随之红移 |
| 迪力（光热杀伤） | 808 nm 激光、1.0 W/cm² 照射 5 min 后 CCK-8 检测的孔板 OD450 读数 0.62 | 该功率密度下肠上皮细胞存活率约 55%，光热有效但需评估暗毒性 |
| 李冲 | 紫外分光光度计在 595 nm 处测得的原始吸光度读数 0.582 | 结合标准曲线计算得出，该组样品浓度为 0.45 mg/mL |
| 杨涵 | 实验测得三组温度原始数值 25.6、26.1、25.8 | 实验环境平均温度 25.8 ℃，波动误差 ≤0.3 ℃，符合实验可控条件 |
| 杨涵（文献） | 文献记录"实验组转化率 32.5%，对照组 18.2%" | 该实验处理方法可显著提升样品转化率，提升幅度达 14.3% |
| 袁桂萍 | 小鼠抑瘤实验中每次治疗后测量的肿瘤体积 | 整理整个疗程的肿瘤体积变化，可以判断治疗组是否真的有疗效 |
| 吴冬 | 同一样品、相同测试设置下溶液与薄膜的发射峰 450 nm 和 510 nm | 该样品从溶液到薄膜后发射峰红移了 60 nm（但还不能证明红移由哪种聚集机制引起） |

迪力强调：I = 1847 a.u. 本身什么也没说，只有放进"溶剂体系 / 浓度 / 激发波长 / 仪器参数 / 对照组"之后，它才变成信息。

吴冬笔记里有一道自问自答，指出了这组概念的一个易错点："红移了 60 nm"保存进另一张表后，能不能又成为数据？**能。数据与信息是相对于使用场景而言的，并非两种永远互斥的东西。**

### 3.1.2 李冲的三重视角："五个反应"里的信息量

李冲的笔记把"信息"放在三个学科视角下审视：

- **信息科学视角**：信息是消除不确定性的量度（香农）；
- **管理学视角**：信息是组织劳动生产的核心驱动力；
- **经济学视角**：信息（数据）是重要的生产要素——他在开场补充说，如今已是大数据时代，经济学界有"数据是第几大生产要素"的提法，数据能卖钱、是资源，甚至找个中介干活都得先付信息费。

他在会上给出的表述是：**数据是人与物质的量，以及人与人、人与物、物与物之间关系的总和，能够被数字化的形式固定下来**——几个苹果是量，看了多长时间手机是人与物之间的关系量，这些量连同文字信息（可以变成 token、再变成数字）一起，构成"计算机的燃料"。

而信息一定包含整理。他说：如果单看数据而没有目的，里面其实没有信息——"这里有几个苹果"这个数据的目的在于指出苹果的数量；没有目的，信息就不存在。信息一定服务于一定目的、被处理过，还需要一定的劳动。

落到自己的实验记录上，他举了一个例子：**"我做了五个反应"，写在实验记录本上是一个数据；"给老板汇报我今天做了五个反应"，就包含了一定的信息量——反映了我的社会劳动、劳动价值。**（迪力当场接了一句"你骗五个反应"，李冲笑答"开玩笑，失效"——课堂气氛可见一斑。）

### 3.1.3 从数据到智慧：DIKW 分层

PPT 引用了管理学中常见的 **DIKW 分层**：数据（Data）→ 信息（Information）→ 知识（Knowledge）→ 智慧（Wisdom），并配了艾略特（1948 年诺贝尔文学奖得主）的诗句："Where is the knowledge we have lost in information? / Where is the wisdom we have lost in knowledge?"（我们在信息中失去的知识在哪里？我们在知识中失去的智慧在哪里？）李冲开场也提到：经济学、管理学界会把数据、信息、知识、智慧分成好几个层次，值得了解。

本次讨论主要把"数据 → 信息"这一级讲清楚了，知识与智慧两级留待以后有更多实践再回头看。吴冬笔记里的一条提醒可以作为这一节的收尾：物理上，计算机运行需要电能；计算任务需要程序与输入。机器学习把数据当作学习材料，由算法调整模型参数，并消耗算力——**仅把大量文件放进电脑，并不会自动产生可靠的知识。**

## 3.2 表示：一切如何变成 0 和 1

### 3.2.1 数据的类型：同一个东西可以同时属于好几类

吴冬的笔记指出，数据分类没有唯一答案，取决于分类角度，而几个角度可以同时成立：

| 分类角度 | 常见类型 | 科研例子 |
|---|---|---|
| 按统计含义 | 数值型 / 类别型 | 收率、温度；溶剂类别、催化剂种类 |
| 按内容形式 | 文本、图像、音频、视频、序列、图结构等 | 实验描述、显微照片、光谱序列、分子连接图 |
| 按组织方式 | 结构化、半结构化、非结构化 | 实验表格、JSON 记录、自由书写的讨论 |

他特别标注了一个初学者陷阱：**类别即使编码成数字也不一定有大小关系**——用 1 表示 THF、2 表示 DCM，不意味着 DCM 是 THF 的"两倍"。

袁桂萍的笔记给出了最全的划分清单，补充了另外两个角度：按数据性质可分定量数据（离散型：细胞计数；连续型：温度、体重）与定性数据（类别数据：血型；顺序数据：满意度等级）；编程语言中还有基本类型（整数、浮点、字符、布尔）与复合类型（数组、列表、字典、对象）之分；按来源与时效又分静态数据与流数据。她的结论是"按结构化程度划分"最常用——这正好引出 3.3 节。

迪力的笔记则把科研中常见的数据类型铺成一张表：

| 类型 | 说明 | 例子 |
|---|---|---|
| 标称（名义） | 只有类别，无顺序 | 分子类别、细胞系名称 |
| 序数 | 有顺序，间距不确定 | 染色强度 + / ++ / +++ |
| 数值·离散 | 可数 | 细胞计数、PCR 循环数 |
| 数值·连续 | 可测，精度受仪器限制 | 波长、OD 值、温度 |
| 文本 | 自然语言 | 论文、实验笔记 |
| 图像 / 信号 | 二维或一维阵列 | 显微图、光谱曲线 |
| 图 / 结构 | 节点加边 | 分子图、相互作用网络 |

### 3.2.2 数字、文字、图片：三种基本编码

所有笔记都回到了同一个核心：计算机无法直接识别文字、图像等内容，一切数据都要转换为二进制 0/1 编码存储和运算，靠的是**约定一套抽象映射规则**（袁桂萍）。吴冬强调这套约定是双向的：编码规则规定如何把文字、数值转换成位串，软件再按同样的规则解析——写进去和读出来必须用同一套规则。

**数字**：整数直接逢二进一（十进制 5 = 二进制 101，即 1×2²+0×2¹+1×2⁰）；负数用补码，最高位表示正负；小数用 IEEE 754 浮点标准，分成符号位、指数位、尾数位三段存储（如 3.14 先转成二进制的科学计数法，再分三段存入一串 0 和 1）。迪力补了一个重要边界：**n 位二进制只能表示 2 的 n 次方个不同值，精度有上限**——位数有限，很多小数只能近似表示，这正是第二次讨论讲过的 Ariane 5 火箭溢出事故的根源（64 位浮点转 16 位整数时溢出）。另外，数值 13 和文本"13"的存储含义不同（吴冬）。

**文字**：通过编码表查表。ASCII 给每个英文字符规定一个数字——'A' 对应十进制 65，存为二进制 01000001；ASCII 只有 128 个位置，表示不了汉字，于是 Unicode 给世界上每一个文字符号（甚至 Emoji 😃）分配唯一编号（汉字"中"是 U+4E2D），再通过 UTF-8 等变长规则转成字节序列。吴冬提醒：中文是按编码规则存储的，**不是先变成图片**。

**图片**：位图把图片打散成像素网格，每个像素用数字记录颜色。任何颜色都可由红绿蓝三原色混合而成，每种原色用 0–255（8 位二进制）表示强度——纯红色像素记作 (255, 0, 0)，即二进制 11111111 00000000 00000000；一张 1920×1080 的图片就是把两百多万个像素的色彩数据按从左到右、从上到下的顺序串成一长串 0 和 1。灰度图单通道，显微图常用 16 位色深（迪力）。矢量图（SVG 等）不存像素、存数学公式（绘图描述）。宽、高、色深和压缩方式都影响文件（吴冬）。

**光谱 / 声音**：连续信号经离散采样加量化变成数字序列，采样率与位深决定保真度（迪力）。

### 3.2.3 分子结构：不是存"图"，而是存编码

分子结构是化学人最关心的一类数据。综合迪力、吴冬、袁桂萍三份笔记：

| 表示方式 | 怎么存 | 特点 |
|---|---|---|
| SMILES 字符串 | 一行特定字符表达分子拓扑，如乙醇 CCO、水 O | 可再经 UTF-8/ASCII 转为 0/1；同一个分子可有不止一种有效写法 |
| InChI / 分子指纹 | 标准化标识符 / 位向量 | 指纹是常用的数值化表示（迪力） |
| MOL 文件 | 原子坐标 + 键连表 | 完整描述还需立体化学、电荷等字段（吴冬） |
| PDB 格式 | 原子列表 + 3D 坐标 (X,Y,Z) + 连接关系表 | 生物计算、药物筛选常用（袁桂萍） |
| 分子图（图神经网络） | 原子是节点、化学键是边，节点与边的属性写成矩阵，最终转为浮点数 | AI 领域的表示法（袁桂萍） |
| 结构式截图 | 像素 | 主要记录像素，程序难以直接读取结构与连接关系（吴冬） |

迪力给出一个统一点：**一切都经过离散化 + 编码，变成一个数字序列。代价是连续世界只能被近似，精度永远有天花板。**

会上吴冬汇报了他向 AI 追问后的三条"边界"，都指向现有表示方法的局限：

1. **同一个分子不止一个有效的 SMILES 写法**；普通 SMILES 不等于唯一编号，也不会自动包含三维构象——不同 SMILES 形式对应的三维构象也不一样；
2. **对聚合物，仅一个重复单元不能完整说明链长分布、序列、端基和样品状态**。他进一步说：人类目前对聚合物的信息表达方式本身也说不清楚这些问题——链长一般用重复单元数或分子量表示，固体形态用人类自己的一套语言描述；
3. **刺激响应结构、纳米粒子等复杂体系的表述维度更不够**：他们组常用光谱变化来阐述刺激响应结构的变化（一旦产生刺激响应，光谱就会变化），但光谱表达也不够——"这次做的纳米粒子和那次做的纳米粒子，差异度有多大"都规定不了。吴冬的判断是：人类对这些对象本身的认知层次就没那么高，设定的观察标准就不够准确。

李冲接话：对它的量、对它的关系都没有明确的认知，就很难转化成数字；关系更难转化成信息，落到计算机上就更难了。这引出了本次讨论的一个方法层面的判断（见 3.2.4）。

**SMILES 为什么成了主流？**吴冬问：以前做结构式的视觉识别，现在大家都转成 SMILES，是因为方便还是好用？李冲答了两点：一是**生态**——围绕 SMILES 有很多现成的程序包；二是**信息量**——SMILES 包含原子之间的连接关系（比如碳氮键），而图片转成像素点后这些关系就没了；更进一步，SMILES 还可以用来写化学反应（A 加 B 生成 C），"图片的话，你怎么让 A 和 B 叠在一起呢？"——化学是生成新物质的东西，能表达反应的表示法才好用。他同时补充：除了 SMILES 还有各种各样的表示方法，各有适用场景。

**"键"其实不在原子里。**迪力在讨论中抛出一个细节：高斯计算文件其实也是数据点，并不含键长键角信息。李冲展开：高斯输入输出文件里的键长键角是程序**按内置规则自动加上去的**——因为在原子层面是没有"键"的；从量子化学角度看，所谓成键就是两团电子云互相重叠。吴冬总结："键"是人类后来加的抽象。这个细节对理解"分子表示"很有冲击力：我们以为最自然的化学概念，在数据层面都是约定与抽象。

顺带一提，聚合物的计算也受制于表示与算力：迪力问聚合物计算是算整个链还是算重复单元，吴冬说目前做法是取几个重复单元做仿真模拟、看构象——100 个重复单元（每个几百分子量）原子数已经不少，高斯或 MD 优化构象都非常耗时。这也是为什么做药物、做蛋白的结构预测会成为 AI 的大领域（李冲会上提到 AlphaFold，转写记录较模糊，大意是它利用进化上的相关信息来理解蛋白质折叠）。

### 3.2.4 从物质到比特：层层转递的缺失

面对"纳米粒子怎么表示"的困境，李冲把问题抽象了一层：从物质到数字，中间要经过好几层——**物质 → 理论框架 → 计算机**。吴冬补充：这相当于信息的层层转递，**每次转递之间都有信息缺失**；一开始对信息的描述准确度就不够，转到后面缺失度只会更高——就像一张图片不停地复制、转码，最后准确度和像素都会大范围降低。

那怎么办？李冲给出的出路是**化繁为简、只盯目标**：如果要优化的只是一个特征——比如"光谱要达到近红外多少以上"——那就只把与它主要相关的变量（比如共轭长度）抓住，别的都不管，一对一批量优化这几个条件。吴冬总结：本质是**构建一个"人类已经确定的物理量"与"你要的最终物理量"之间的关系**。这个思路正是第四次讨论"特征与标签"的入口。

## 3.3 结构化与非结构化

### 3.3.1 有没有"形状"，决定好不好用

综合各份笔记，三类数据的定义：

- **结构化数据**：有预定义模型（schema），固定格式、行列分明、字段类型确定——电子表格、数据库表、CSV、关系型数据库（MySQL、Oracle）；
- **半结构化数据**：不遵循严格的表格结构，但用键、标签或层级表达关系，不同记录的字段可以不同——JSON、XML、HTML、YAML，以及带元数据的仪器导出文件、CIF、OME-TIFF；
- **非结构化数据**：没有预定义数据模型——论文 PDF、手写记录、显微原始图、自由文本、音视频。袁桂萍笔记补充：这类数据占现实世界数据的 80% 以上。

迪力给了一个直接的判断法：**能不能不读内容、直接按字段名查询和统计？能 → 结构化；不能 → 非结构化。**吴冬补了两条操作性提醒：不要仅凭文件后缀判断结构化程度；"Excel 中粘满截图，并不会因此成为可直接统计的实验数据库"。

杨涵在会上的盘点很典型：实验记录里加了多少样、用了什么温度、培养了多久——这种明确的、可统计可量化的参数是结构化数据；拍的照片、录的视频、自己记录的文字——没法直观统计、需要二次处理的东西是非结构化数据。她同时指出：**正常科研生活中两者是互相结合的**；而且结构化与非结构化数据都有好坏之分——非结构化数据只要本身准确，经过二次处理就可以变成可用的结构化数据。

### 3.3.2 科研数据盘点

把五份笔记的盘点合并成一张表：

| 成员 | 结构化 | 非结构化 | 半结构化 |
|---|---|---|---|
| 迪力 | 96 孔板 OD 读数表（孔位/分组/浓度/OD/存活率）、浓度–存活率汇总表、光谱峰值表（fw、λmax、I）、化合物库 CSV（SMILES+分子量+logP）、文献计量表 | 荧光与共聚焦显微图、TEM 图、论文 PDF 全文、手写实验记录本、未标注条件的原始光谱文件、组会 PPT 与研讨笔记 | Zotero 的 RIS 条目、带 metadata 的 .sp/.tif、NMR 的 FID+参数头 |
| 袁桂萍 | 光物理性质测定（发射/吸收曲线、AIE 曲线）、细胞摄取量随时间变化 | 示意图、反应进程图（直观展示颜色或发射变化） | — |
| 杨涵 | 实验记录表（温度、时间、浓度、样本数）、检测数值、统计报表、对照组/实验组参数、量化指标数据 | 实验原始图像、分子结构可视化图谱、文献正文段落、实验日志文字、现场观测记录、访谈文本 | — |
| 李冲 | EndNote 文献库（统一命名和编码） | 随机放置的一些实验数据，没有被统一命名和分类 | — |
| 吴冬 | 逐次实验条件与收率表、UV/PL/GPC 数值导出文件（有明确列定义时）、带命名字段的 JSON 仪器记录、分子连接表 | 光谱截图、显微照片、薄膜照片、自由书写的实验记录、论文正文 | JSON、XML 记录 |

吴冬的表格里最有价值的一列是"**转为可分析数据的关键**"：结构化表格要"一行一次实验、单位明确、同一列含义一致"；光谱导出文件要"保存横纵坐标及单位，并关联样品与测试条件"；照片类要"保留原始文件，补充拍摄条件、标尺和样品编号"；自由文本要"提取样品、条件和结果，保留原文便于核对"。

### 3.3.3 把整理劳动放在日常：一次实验一条记录

吴冬的笔记给出了可直接照做的方案：**给每次独立实验一个唯一编号，用它连接条件表、原始光谱与处理结果**；一次实验可以对应多份文件，不必把所有内容强行塞进一个单元格：

| 实验编号 | 溶剂 | 温度/℃ | 时间/h | 分离收率/% |
|---|---|---|---|---|
| R001 | THF | 25 | 12 | 42 |
| R002 | THF | 50 | 12 | 68 |

（简化假设示例。实际记录还需底物结构、投料量、浓度、催化剂、气氛、批次及原始文件位置。）整理原则：**一列一种含义；单位统一；尽量不合并单元格；样品编号保持一致。**特别地：**未测收率应记为"未测"，不能填 0——0% 是测量结果，和缺失值不是一回事。**

李冲把这个思路推广成了小课题组的两条路线：

1. **日常积累**：从现在开始对数据做结构化管理——每天下载的 PDF 按日期编码、放进固定的文件夹；记录包含日期、来源，条件尽可能统一，单位也统一。"把长时程的劳动放在日常工作中"，慢慢就结构化起来了。他自己就是这么建 AIE 文献库的：从文献网站按关键词每日检索、手动下载（自动爬虫会被封，靠平常看文献时"随手下一下"），日积月累已有近 4000 篇，甚至与 AIE 不太相关的文献也收了进去；
2. **集中突击**：如果突然来了一个目标明确的任务，就花几个月专门的时间（或者雇人、用技术手段）把大量数据补齐。

袁桂萍当场问：能不能用同样的思路给自己感兴趣的领域也搭一个文献库？李冲说可以，但要求数据量大，"没事就下一点存一下"——需要一定时间的劳动来实现。

讨论最后李冲说了一句值得记住的话：**计算机并不能减少劳动，它只是把劳动转换到了不同的地方、不同的时间上去了。**

## 3.4 标准：什么样的数据才算好数据

### 3.4.1 可操作的标准清单

这一问五人都给出了清单，各有侧重，合并如下：

| 标准 | 要点（综合迪力、吴冬、杨涵、李冲） | 科研中怎么检查（吴冬） |
|---|---|---|
| 准确可信 | 仪器经过校准，有空白与对照，有重复；无篡改、无错误记录 | 单位或抄录有无错误？保留原始记录了吗？ |
| 关键内容完整 | 关键元数据不缺：浓度、溶剂、温度、激发波长、狭缝、仪器型号、测试方法 | 样品身份、浓度、状态、测量方法是否齐全？ |
| 一致可比较 | 单位统一、命名统一、批次可比；方法差异可识别 | 分离收率与核磁收率是否区分？溶液和薄膜是否混在一起？ |
| 覆盖目标范围 | 包含将来要预测的对象和变化（吴冬、李冲特有） | 是否只测一种底物、一种溶剂或全是高收率实验？ |
| 可追溯可复核 | 谁、何时、哪台仪器、原始文件在哪、经过哪些处理步骤 | 哪个批次、谁测的、怎样扣背景、是否删除过点？ |
| 不确定性明确 | 记录独立重复、误差与检测限；区分未测和未检出（吴冬特有） | 测量有多稳定、哪里未知？ |
| 可读取可复用 | 格式开放、许可清晰、有数据字典说明每个字段；别人用你的数据也能画出类似的图（迪力） | 能否获得原始数值、字段说明、通用格式和使用条件？ |
| 可查找可访问 | 有唯一标识（如 DOI），存放在稳定位置（迪力） | — |
| 适合具体任务 | 好数据首先要适合任务：对观察峰位趋势足够的数据，不一定足以比较绝对发光强度（吴冬） | — |
| 低获取与结构化成本 | 不需要额外劳动或仅需轻微劳动就能获取和结构化（李冲特有） | — |
| 时效性（"新"） | 贴合当下研究场景与实验条件（杨涵特有） | — |

迪力在会上把他的六条标准（准确、完整、一致、可追溯、可复用、可查找可访问）逐条展开讲了科研语境下的含义，其中"一致"的例子最形象：**不能一个测吸光度、一个测透射率，还有人自己去换算**——单位要一致、命名要一致。

杨涵的"准、全、净、齐、新"五字诀与上表高度重合，其中"净"（无冗余、无异常噪声、无重复无效数据）是上表没有单独列出的角度。

吴冬笔记里有两个重要概念：

- **元数据**（metadata）：是在说明数据的来龙去脉。"发射峰 480 nm"是结果；样品编号、溶剂、浓度、激发波长、狭缝、温度、日期和处理方法，是帮助解释结果的元数据。**没有这些说明，两个 480 nm 也未必可直接比较**；
- **FAIR 原则**：科研数据管理中常用的框架——可发现（Findable）、可访问（Accessible）、可互操作（Interoperable）、可复用（Reusable）。它强调人和机器都能找到并理解数据，但**不等于全部免费公开，也不保证实验本身准确**。

### 3.4.2 "多"和"好"哪个更重要

五人的基调一致：**好更重要**，但自由讨论把这问推进了颇有意思的一步。

"好更重要"的理由：

- 迪力：数据再多，如果条件是混乱的，可能会把结论带偏——这个数据就被污染掉了。很多人不给你条件、直接给结果，你用这些结果时会默认一个前提条件，结果就把实际应用带偏。"就算数据少，也得把数据洗干净：在同样的前提条件下得到一个结论，然后再去扩充。"他的笔记里还有一句更狠的：
  > 脏数据的危险在于它不报错——它会系统性地把结论带偏，而你从结果上看不出来。
- 杨涵：海量劣质数据（错误、残缺、杂乱）会导致分析偏差、模型失真、结论失效；
- 迪力笔记的经验法则：**先保证 200 条干净、元数据完整的数据，再谈 20 万条**；小数据加严格条件，胜过大数据加混乱条件——因为模型学的是条件与结果的映射，条件里的噪声一大，学到的就是假规律；
- 吴冬：先保证基本质量与任务相关性，再增加数量和覆盖范围；错误标注、系统性偏差和缺失条件不会因数量增加而自动消失。他举的例子：1,000 条来自同一底物同一条件的记录，和 100 条覆盖不同底物与温度的记录——前者适合估计该条件下的波动，后者才可能支持学习跨底物、跨温度的关系。**不能脱离目标，仅凭条数判断价值。**他的讨论题同样切中要害：把同一条数据复制 100 次，与做 100 次独立实验有什么区别？——复制不增加独立证据；独立重复可估计波动，但仍不一定扩大条件覆盖；
- 袁桂萍：数据多但不好，不就只是占用内存吗？她还有一个观察：现在 AI 在化学领域本来就存在不太好使的地方，没有好数据去训练，AI 就不会迭代生成让人满意的信息——"我们的科研能力都是随着经验与积累逐步提高的，那些经验对我们来说就像是数据；同理，AI 也需要。"

李冲则提出一个重要的补充视角（本次讨论他独有的见解）：**在好的情况下要尽可能多，而且"好"需要再补一个定义——尽可能囊括要描述的目标的搜索空间，有代表性。**他打了个比方：给一座山做等高线图，如果采样点踩得很好但网格太宽，就会丢掉大量细节——丢掉的细节严重时能"把一座山变成一个盆地"。迪力接了一个更直观的比喻：就像屏幕分辨率，480P 能看出是个人，4K 下面连头发丝都看得清——理想状态当然是又好又多。

但李冲随即指出了化学的现实困境：**目前对化学来说最难的地方是数据都不够。**AIE 领域干了 20 年，有记录的分子数量可能上万，但相对要研究的问题空间仍然很不充足。（数据从哪来、贵不贵，见 3.5.3。）

会上袁桂萍追问了一个很实际的问题：我怎么判断一份数据是好的还是坏的？李冲的回答：好和坏是相对的——**先定义你的目标**；在目标确定之后，好数据的标准就是上面这些条目，再加上"尽可能布满整个空间"这一条。

## 3.5 开放性问题：文献数据与机器学习的门槛

### 3.5.1 文献里的数据为什么经常"不好用"

袁桂萍第一个发言，从生物和合成两头举例：

- **生物领域**：细胞实验、动物实验受外界干扰很大——不同人的培养方式、操作方式、甚至加样方式不一样，都会导致结果不稳定；有的实验有概率重复不出来。有些文献为了保护自己的研究经验，会**隐藏关键操作细节**；还有些人会**挑选自己满意的数据**，导致数据不可靠；
- **合成领域**：作者实际的条件变了，但在实验部分换了一种方式描写（"口头禅式"的改写），照着文献的方法可能合不出相关分子。

综合五份笔记与自由讨论，"文献数据不好用"的原因可以归成六类：

1. **只报结论，不报原始值**——给 IC50 却不给剂量–反应原始数据；说"增强 20 倍"却不给绝对量子产率与参比标准（迪力）；
2. **条件缺失**——溶剂、浓度、激发波长、狭缝、温度、仪器型号常不完整，导致跨文献不可比（几乎所有人）；
3. **单位与定义不统一**——ROS 有时用相对荧光倍数、有时用绝对量；"存活率"的归一方式各家不同（迪力）；产率的写法也不统一，有写 0.几 的、有写百分号的（李冲）；
4. **选择性报告（发表偏倚）**——只发表好看的结果，阴性数据不发表，数据本身带系统性偏差（迪力笔记；李冲在会上把它补成一个独立原因："文献的数据大部分都是[成功的]，只报道正确的案例，没有负面案例，很大一部分数据空间被省略掉了"；杨涵笔记同）；
5. **数据锁在图片里**——曲线以像素形式躺在 PDF 中，只能人工读数，引入数字化误差（迪力）；文献天然不是为机器检索组织的（李冲、吴冬）；
6. **批次效应**——细胞代次、染料纯度、光照剂量的差异使复现困难（迪力）。

迪力的总结一针见血：

> 文献里的数据是为了说服审稿人而组织的，不是为了被机器消费而组织的。

**为什么负面数据不发表？**针对第 4 条，吴冬给出了一个"研究者立场"的解释：实验数据是课题组的私有财产——所有数据加起来相当于一个完整的技术路线（甚至专利途径），全部披露相当于替别人把实验做了。多数课题组的现实考量是：报道好的发文章，坏的留下来，将来可以打包转化、给别人做的时候规定适用范围——但他不告诉你，你就不知道他的技术适用范围。"他不能把好的坏的都给你，那相当于白打工。"迪力补了一句：坏的数据咱们是拿来做对照的。（这一段是对学术生态的现状描述，课程版如实记录。）

**打假插曲。**迪力由此想到一个问题：之前很多论文打假，那些问题数据是怎么被发现的？明明都是图片。大家的讨论：打假多发生在子刊——子刊要求上传原始数据，能查到线索；多数化学期刊并不要求上传所有原始数据；吴冬补充：有的大型出版系列比较精明，十年前就开始逐步完善原始数据上传制度，可以从那边找到很多线索。

**CIF 文件名之痛。**李冲补充了一个结构化学人都有体感的例子：单晶结构虽然自带坐标（吴冬指出），但 CIF 文件里的化合物名和文章里实际的分子简写往往**对不上**——用今天的话说，这个信息不是结构化的、不是一一对应的，信息量就偏低，你得先付出很大劳动去找、去核对。而且单晶结构反映的是固体结晶状态下的构象，并不一定是液体中的状态（迪力）。

### 3.5.2 从文献里"挖"数据：成本、工具与 AI 的角色

文献数据既然锁在文字和图片里，获取它就是一门苦力活。李冲的几个观察：

- 数据埋在大量**需要领域知识**的文字里——"随便来个人，他不懂 AIE，就不知道这图啥意思"；熟悉的人找一张图也要一两分钟，新手就非常难找。文献天然不是为了让人提取数据而写的，它主要是为了传达设计思路和理念（吴冬：设计思路的逻辑性的东西）；
- 人工提取成本很高：以前有团队做文献数据提取按条计价（转写记录为"十港币一条"，项目名不清），即便这样也不见得有人接单——纯耗时间。李冲的估算：十分钟找一条，一天 8 小时也就 48 条；经常看完一篇文献才能找到一条，还得把 SI 文件下载下来。迪力的判断是这活"本科生可能都不太够，说不定还得雇个硕士，价格都很贵"；
- **程序辅助**：可以用 Python 对文本扒关键词（袁桂萍），现在大模型进来之后成本又低了一些（李冲："现在可能成本低了一些"）。但他提醒：越是抽象、越是框架性的判断（比如区分某个 AIE 问题的机理类型），大模型就越不好使——关键词级别的提取没问题，框架级别的理解还不行。

**迪力的实战演示**是本次讨论最有信息量的环节之一。他用一款 AI 知识库工具（转写记录作"work body"，工具名待核），接上李冲分享的 AIE 领域文献库，检索"808 nm 激光光热治疗常用功率"（转写中 PDT/PTT 混写）：三千多篇文献里自动筛出 54 篇相关文献，并列出各文献的功率记录。他当场指出三个问题：

1. **结果不全**——全文搜索的限定条件加多了，几千篇里只抓出 54 篇；
2. **记录五花八门**——功率范围有写 1.0 到 2.0 的、有带斜杠的，单位各不相同，很难统一（李冲：不同激光器厂家还不一样）；
3. **AI 会出错**——大模型存在事实性偏差（幻觉），筛出来的值需要在对应文献里再核实是不是真正的值。

他的结论："靠 AI 这种工具挑选出来的数据之后，可能还要再去核实，这也是一个很花时间的地方。"但整体上他还是认为值得：人工看不一定能看这么多文献，这个例子用的免费模型跑了两三个小时。袁桂萍当场问：以后想要什么实验条件，能不能直接在库里搜、让它自动总结？答案是肯定的——只是要接受"筛出 54 篇、其中还有些对的不对的、仍需人工判断"的效率。

李冲借这个例子给大家补了一课 **RAG（检索增强生成）**的原理：所谓"库里的全文搜索"并不是把整篇文章都塞给大模型（一篇文章几千字，token 消耗太大，平台对 token 也有限制）；而是先把库里的每段内容转换成一段数字（向量），把你的问题也转换成数字，按数学上的相似度比对，把最接近的段落抽出来，和你的问题一起发给大模型——这样模型的回答就会非常接近原文。"这个叫知识检索增强，是 RAG 系统。"他同时回应了迪力关于本地部署的问题：本地部署模型或调 API 都可以做这类提取（识别关键词、识别分子结构式）。

对"AI 挖数据到底靠不靠谱"，李冲的立场是：**初步筛选肯定比没有强**——有 AI 肯定比以前好太多了，他原来构建一个数据库要一个人不断积累一年多，现在成本已经降下来了；大模型总会有幻觉，但即便如此，"至少比人工洗强很多"。洗数据的痛苦大家都有体感（吴冬："洗数据非常痛苦"），AI 的帮助是真实的。

### 3.5.3 机器要"学出规律"，数据至少需要什么条件

袁桂萍的课前回答是：可靠、可重复，"是不是也需要具备一定的逻辑关系？"——数据和信息之间似乎存在逻辑上的先后。这个问题在自由讨论环节引出了本次讨论最认真的一场集体辨析：**训练数据所需的逻辑关系，是先天的还是后天的？**

- **迪力**：至少输入和输出要先有一个对应——比如激发波长是多少、发射波长是多少，先把对应起来，后面再去找规律；
- **吴冬**：想起做生信、做统计生态学的——他们一开始并不知道数据和结论之间的关系，通过生信统计找到关联之后，有一部分逻辑关系就是**后面赋予**的；
- **李冲**：先天应该有低层次的结构——比如一段合成最终有一个产率，不管它写成 0.几 还是百分号，先天确实有东西；然后我们从更高层次把它抽出来、统一起来（统一成百分号或小数）。从零开始不太可能，一定是先有一点东西；
- **杨涵**：肯定前面会有一点，但后面我们可以通过结果分析出更多的逻辑，再解释它；
- **迪力**再补充：首先得有一套对应（什么温度、什么前提条件下），然后我们再从这些对应的条件中分析出规律——抽象成更高层的。

这场讨论的共识可以概括为：**数据先天至少要具备"输入–输出对应"这一最低层次的结构；更抽象、更框架性的逻辑可以事后整理与赋予——但整理的前提是先天有东西可整理。**

吴冬的笔记则给出了七条更完整的"最低条件"，以预测反应收率为例：

| 最低条件 | 以预测反应收率为例 |
|---|---|
| 映射真实存在 | 输入 X 与输出 y 之间确有稳定的对应关系，而不是随机 |
| 关键变量必须在输入里 | 提供底物、催化剂、溶剂、温度等；缺了决定 y 的变量就永远学不会——不记录光功率密度，就学不出光热规律 |
| 记录与目标正确对应 | 结构、条件和收率属于同一次实验；标签定义一致，缺失有说明 |
| 有足够独立的变化与覆盖 | 覆盖相关底物、条件和低收率结果；样本量取决于任务，没有统一最低条数 |
| 标注一致、噪声可控 | 标签定义必须明确（"存活"的阈值到底是多少）；记录重复与波动 |
| 分布一致 | 训练与预测来自同一分布；跨批次、跨仪器必须校正 |
| 留出验证集 | 才能区分"学到了规律"和"背住了答案" |

他的笔记还预告了几个第四次讨论的关键词：**特征**（输入描述）、**标签**（希望预测的答案）；**数据泄漏**——不要让测试答案或预测时无法获得的信息参与训练，否则模型看起来很准却无法预测新实验；**无监督学习**不要求人工标签，**自监督学习**可从数据本身构造目标，但它们同样需要质量与覆盖，而且**学到相关性不等于证明因果机制**。李冲笔记的五条概括与之呼应：符合最终目标的需要、真实、数量多、信息量高、分布广泛——**能够描绘目标函数的空间**。

**50 条数据能不能直接搭库训练？**迪力结合自己演示的那个 AI 筛选结果问：五十多条数据有点少，而且还需要化合物的结构式，能不能直接搭个库？李冲的回答：**看目标**——先定义目标，再按目标难度评估需要多大数据量、最后要达到什么精度。（呼应 3.4.2：不能脱离目标谈数据。）

**化学的数据从哪来？**李冲算了一笔账：对化学、生物来说，要搜索的问题空间非常大；AIE 做了 20 年分子上万，仍然不充足。如果想自己造样本，按最简单的算，一个样本仅材料成本就要约 50 元，还不算劳动力。他介绍了 AI 制药领域拿数据的两条路：一是**从头模拟**——先通过大量理论计算或分子动力学模拟，再随机生成一大批分子去"合理碰撞"看能不能接上，然后筛选；二是**存量积累**——多年的合成实践本身就积累了大量结构化数据。迪力补充了第三种：高通量筛选，一次做很多样、上百个。

吴冬随即给"高通量筛选"泼了一盆有内容的冷水：高通量筛选成本很高，而且**学科适配性差异巨大**。药学领域推广得快，是因为不管筛到活性化合物、先导化合物还是进入下一阶段的化合物，**每个阶段的产物都能卖钱**——相当于挖矿，挖到哪一步都有产出；而对很多学科来说结果只有 0 和 1（要么好要么坏），只有挖到最好的那一个才有价值，投入很多钱最后没挖到就完蛋——这种学科就不适合。（这段对学科商业生态的判断为吴冬个人观点，课程版如实记录，供讨论。）

## 本章小结

1. **数据与信息的分界在语境与解释**：数据是对事物状态的原始记录，信息是数据被放入语境、整理和解释后消除不确定性的产物；数据是载体，信息是解释结果——没有语境的数据就是噪声。两者相对使用场景而言并不互斥：一条提取出的"信息"存进表格后，对下一个问题来说又是数据；
2. **一切皆 0/1，靠的是约定编码**：数字（二进制、补码、IEEE 754）、文字（ASCII → Unicode/UTF-8）、图像（像素网格 + RGB）、光谱（采样 + 量化）、分子结构（SMILES、MOL、PDB、分子图）都经过离散化 + 编码变成数字序列；代价是连续世界只能被近似，n 位编码的精度永远有天花板；
3. **分子表示是化学人的特殊一课**：分子结构不是存"图"而是存编码；SMILES 成为主流靠的是生态与信息量（能表达连接关系与反应）；"键"在原子层面并不存在，是程序按内置规则加上的人类抽象；同一分子有多个有效 SMILES 且不自带构象，聚合物的链长、序列、构象尚无好的数字表示——复杂体系表示维度的不足，根子在于人类认知与观察标准本身不够准确。从物质到理论框架再到计算机，层层转递、层层缺失；务实的出路是固定目标、只抓与目标物理量相关的主要变量；
4. **结构化与否看"能不能按字段查询"**：结构化（schema）、半结构化（JSON/XML/CIF）、非结构化（PDF/图片/手写）三分；科研数据两者并存且互相结合，非结构化数据只要本身准确，经二次处理可变成结构化。好习惯是把一次实验整理成一条记录：唯一实验编号 + 完整元数据 + "未测≠0"，把整理劳动放在日常——计算机不减少劳动，只是把劳动转移了时间和地点；
5. **好数据有可操作的标准**：准确、完整、一致、可追溯、不确定性明确、可复用、可查找可访问（FAIR），再加上两条化学语境的关键项——适合具体任务、覆盖目标搜索空间。"多"与"好"的共识是先好再多：脏数据不报错，会系统性把结论带偏；而"好"的完备定义包含对搜索空间的代表性覆盖——这对数据普遍偏少的化学尤其重要；
6. **文献数据不好用，因为它是为人组织的，不是为机器组织的**：只报结论不报原始值、条件缺失、单位不统一、选择性报告（负面数据缺失）、数据锁在图片里、批次效应，是六大系统性原因。AI（RAG 检索 + 大模型初筛）大幅降低了挖数据的成本，但筛出的数据仍需人工核实，越是框架性的判断 AI 越不好使；机器学习对数据的最低要求，是输入–输出对应关系真实存在、关键变量在场、分布与目标一致——这正是第四次讨论的起点。

1. **分子"同一性"的表示问题在本章再次出现**（承接第二部分）：同一分子有多个有效 SMILES 写法、不同写法对应不同三维构象——如何在机器表示中统一？SMILES 之外的表示方法（InChI、分子指纹、分子图）各适用什么场景？留待分子表示专题；

6. **数据量与问题空间的差距**：化学问题空间巨大（AIE 20 年才上万分子）、造样本成本高，数据量与模型复杂度如何匹配？高通量筛选、自动化实验室在什么学科条件下值得投入？

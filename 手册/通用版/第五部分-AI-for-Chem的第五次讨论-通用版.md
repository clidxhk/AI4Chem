## 引言

上一章介绍了机器学习如何从实验数据中建立预测模型，以及如何评价这些模型。
假设在日常科研中，你需要整理十篇文献中的分子发射光谱数据。

通常有两种借助 AI 的方式：
第一种是向 AI 提问，请它告诉你应该提取哪些光谱参数，然后你自己逐一打开十篇 PDF，手动寻找发射峰并复制粘贴到表格中。
第二种是把十篇文献交给一个能读取文件和生成表格的应用，由它自动逐篇阅读、提取发射峰与测试溶剂、核对缺失项，最后直接交付一份整理好的表格供你验收。

这两种做法都用到了 AI，本质差别在于**具体的操作是由人来做，还是由 AI 接手**。
本章从这个差别出发，探讨 AI 怎样从“陪人聊天”走向“帮助人完成一项实际科研工作”。

本章围绕五个核心问题展开：

1. **发展**：从回答单次问题到推进整项任务，执行方式发生了什么变化？
2. **依据**：AI 怎样取得文献与数据，回答怎样与原始出处对应？
3. **Skills**：怎样把化学科研中成熟的专业方法保存下来，供后续复用？
4. **市场**：模型本身、运行框架与客户端产品之间是什么关系，该怎样选择？
5. **接入与付费**：科研工具怎样连接模型服务，费用与资源怎样计算？

## 5.1 发展：从回答问题到推进任务

### 5.1.1 从熟悉的 ChatGPT 说起

打开 ChatGPT 或类似产品的网页，输入“帮我把这段聚合物摘要翻译成中文”，几秒内就能得到译文。
你还可以接着要求“语气更学术一点”“保留专业术语”“压缩到一百字以内”，它会结合前面的对话继续调整。
这种用自然日常语言交互的方式，是许多人认识现代 AI 的起点。

**ChatGPT 是一个典型的 ChatBot（聊天机器人）应用。**
用户发送消息，软件以对话的形式予以回应。
同一个聊天窗口，可以用来询问概念、翻译文本、润色论文或编写简单脚本。

支撑这种对话能力的核心是**大语言模型（Large Language Model，LLM）**。
大语言模型在海量文本数据中进行预训练，学习了语言表达规律、专业知识与逻辑组织形式。
当你提出要求并附带材料时，模型根据当前的输入预测并生成后续的文字。

**在纯粹的 ChatBot 形态下，大语言模型主要扮演“大脑与笔”的角色。**
它负责理解你的语言并生成文本，但它本身无法直接操作你的本地电脑：不能自主翻阅你硬盘里的文件夹，不能运行化学绘图软件，也不能替你点击网页下载最新的文献。

### 5.1.2 从回答一个问题，到完成一项工作

在整理十篇文献的场景中，如果单靠聊天对话，研究者必须充当“搬运工”：自己找文件、复制文本喂给模型，再把模型的回答复制出来存入表格。

如果希望软件能分担更多现实工作，就必须把“阅读本地文件、提取指定字段、将结果写入表格”这些具体的现实操作串联起来。

工作过程中往往需要根据中间结果做出判断：
例如，第一篇文献提取顺利，直接写入表格；第二篇文献是扫描件图片，无法直接复制文字，系统就需要转而调用文字识别工具；第三篇文献缺少光谱溶剂说明，系统就需要翻看支持信息（Supporting Information）进行核实。

这时，系统需要根据当前步骤的执行结果，自主决定下一步该调用什么工具，直到整项任务完成。

**围绕一个明确目标，能够自主判断行动、使用工具，并根据环境反馈持续推进工作的 AI 系统，称为 Agent（智能体）。**

![Agent 中模型提出行动、环境返回反馈并继续执行或停止的循环](https://clidxhk.github.io/AI4Chem/手册/通用版/图片/第五部分/agent-loop.png)

*图 5-1　Agent 的核心执行循环。来源：[Anthropic，Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)，原图。*

图 5-1 展示了 Agent 最基本的运行逻辑：
- **Human（人类使用者）**：负责交代任务目标、提供初始材料与边界约束。
- **LLM Call（模型判断）**：模型根据当前目标与进展，分析接下来该做什么，并提出行动指令（Action）。
- **Environment（环境与工具）**：外部程序执行该行动（如读取文件、检索数据库或运行代码），并将实际结果（Feedback）返回给模型。
- **Stop（终止判断）**：模型检查结果是否已满足要求。若满足则向人类交付成果，若未满足则继续下一步循环。

### 5.1.3 从聊天机器人到日常助手的演进台阶

从简单的对话框发展到能够接管复杂任务的 Agent，技术主要经历了四个关键台阶：

1. **自然语言对话的普及（2022 年底）**：
   以 ChatGPT 的发布为标志，大语言模型展现出出色的通用理解与表达能力，让非计算机专业的研究者能够直接用日常语言调用 AI 辅助科研。
2. **连接外部工具（2023 年）**：
   纯语言模型无法获知私有数据，计算能力也受限。2023 年，**工具调用（Tool Use / Function Calling）**机制被引入：模型能够按照规范输出结构化指令，调用计算器、搜索引擎或数据库查询接口，模型开始拥有了感知外部数据和操作外部程序的能力。
3. **工作流与多步协作（2024 年）**：
   面对复杂的长流程任务，研究者开始将预先设计好的固定步骤（Workflow）与模型的灵活判断相结合，并尝试让多个专职 Agent（如检索 Agent、提取 Agent、核对 Agent）互相配合，共同完成一项较大规模的工作。
4. **端到端自主任务执行（2025 年至今）**：
   以 Claude Code、Manus 等产品为代表，Agent 开始直接面向完整现实任务。用户只需交代一个目标（如“分析这个目录下的光谱数据并生成汇总网页”），Agent 即可在给定的工作空间内自主读取文件、编写代码、运行排错并最终交付成品。

从 ChatBot 到 Agent，AI 的角色从**“被动回答提问的咨询者”**变成了**“在约束下主动推进任务的协作者”**。

## 5.2 依据：先取得资料，再检查回答

### 5.2.1 上下文：模型眼前的参考书

在聊天窗口中直接问 AI：“这篇论文合成 P1 的产率是多少？”
如果此前从未提供过该论文的内容，模型无法凭空回答。只有把实验部分的文字贴进输入框，它才能据此给出答案。

**上下文（Context）是模型在当次处理时能够看到的全部信息。**
它可以包含你的提问、系统设定的角色、此前的对话记录，以及刚刚读取的文献段落或外部工具返回的查询结果。

可以把大语言模型想象成一位开卷考试的学生：
- 模型的训练参数相当于它的常识与语言积累；
- 上下文则是摆在它课桌上的参考书与草稿纸。
- 参考书里有什么内容，它这一步才能精准参考什么内容。

一次能够放进参考书的内容是有限度的，这就是**上下文容量（Context Window）**。
虽然现代模型的上下文窗口已经能够容纳几十万甚至上百万字，但在长任务中，依然需要合理安排放入的内容，确保关键文献与要求能够被模型清晰关注。

### 5.2.2 检索增强生成（RAG）：先查资料，再作回答

面对刚发表的新文献、课题组内部的实验记录或几百页的学位论文合集，研究者不可能每次都手动复制海量文本喂给模型。

让应用先替你查阅资料，再把查到的有关片段交给模型作答，这种机制就是**检索增强生成（Retrieval-Augmented Generation，RAG）**。

整个工作过程包含四个步骤：

1. **接收提问**：明确提问意图以及需要检索的文件范围。
2. **检索段落**：在目标文档集合中查找与提问最相关的几个段落、表格或图表说明。
3. **注入上下文**：将检索出的原文片段与原始提问拼装在一起，作为参考材料提供给模型。
4. **生成回答**：模型完全基于眼前的参考材料组织答案，并标注信息来自哪篇文献的哪个位置。

![用户提问后先检索相关文档，再交给语言模型生成回答](https://www.elastic.co/docs/solutions/images/elasticsearch-reference-rag-schema.svg)

*图 5-2　RAG 系统工作机制。来源：[Elastic，RAG system overview](https://www.elastic.co/docs/solutions/search/rag)，原图。*

如图 5-2 所示，RAG 的本质就是**在模型回答之前，自动为它补足所需的准确资料**。
新增的文献和实验数据保存在外部数据库中，模型本身不需要重新训练，只需要在回答时查阅这些新资料即可。

### 5.2.3 科研资料的三种入口

在实际科研中，Agent 通常从以下三个入口获取资料，核对时关注的重点也各有不同：

| 资料入口 | 适合取得什么 | 怎样检查真实依据 |
|---|---|---|
| **本地文件** | 硬盘指定目录中的 PDF、数据表格、代码脚本 | 确认读取的文件路径正确，核实表格、图注与识别文本是否完整 |
| **已整理知识库** | 课题组归档的文献库、操作规范、往期报告 | 检查收录的文件版本是否最新，能否定位到具体章节或原文片段 |
| **联网搜索** | 刚刚上线的新论文、官方产品手册、公开性质数据库 | 打开检索返回的原始网页链接，核对发布机构、发布日期与正文原句 |

无论通过哪种入口，**资料检索的目的是为回答提供坚实的可查据证**。
如果检索到的段落本身不包含所需结论，模型就应该如实说明材料不足，而不是根据预训练常识进行猜测。

### 5.2.4 化学结论必须连同测试条件一起提取

在化学研究中，“提取事实”有一个极为重要的原则：**离开测试条件的数据没有科学意义**。

假设请 Agent 从文献中提取“聚合物 P1 的最大荧光发射波长”。
如果系统只返回一个数字：`520 nm`，这个回答是不合格的。

合格的科学提取必须包含测定该数值时所处的状态与条件：
- 该数值是在稀溶液中测得，还是在固态薄膜中测得？
- 如果是溶液，溶剂是四氢呋喃（THF）、水还是二氯甲烷？浓度是多少？
- 激发波长是多少？对应的是原文的图几或表几？

| 提取要素 | 在化学数据中的具体含义 | 缺少该要素的后果 |
|---|---|---|
| **研究对象** | 化合物明确编号、结构名或样品批次 | 混淆母体化合物与改性产物 |
| **核心数值与单位** | 发射峰位（nm）、量子产率（%）、产率（%）等 | 数值失真或单位错乱 |
| **必要测量条件** | 聚集状态（溶液/薄膜/粉末）、溶剂、浓度、激发波长 | 无法对比不同文献间的性能优劣 |
| **来源定位** | 对应文献的 DOI、正文页码、具体图表号（如 Figure 2b） | 无法回溯核对原始图谱 |

**提取数据时，必须把数值、测试条件与原文位置绑定在一起。**
这样提取出的表格，才具备可重复性与后续分析的价值。

### 5.2.5 检查 AI 回答的“查证三问”

无论 Agent 是通过阅读本地文件还是通过 RAG 生成了科研总结，研究者在核查结论时，都可以直接对照以下三个问题进行检验：

1. **出处在哪里？**
   要求 AI 明确指出证据出自哪篇文献、哪个文件、哪张支持材料。如果给不出明确来源，该结论暂不可信。
2. **原文哪句话或哪张图支持？**
   打开对应出处，核对原文语句或图表数据是否真正表达了该含义，排除模型断章取义或自行发挥的可能。
3. **测试条件与单位是否完全一致？**
   核对样品状态、测量溶剂、浓度单位是否准确对齐，避免把特定条件下的特例当作普遍规律。

AI 可以极大地加速粗筛与归纳文献的过程，但**科学结论的最终裁决权始终在研究者手中**。

## 5.3 Skills：把专业方法变成可复用规程

### 5.3.1 什么是 Skill：把成熟科研做法变成操作规程

每位化学研究者在阅读文献或处理实验数据时，通常都有自己的一套成熟习惯。
例如，精读一篇文献的前言时，大家普遍习惯按以下逻辑拆解：

1. 本文针对的核心科学问题是什么？
2. 前人工作已经解决到了什么程度？
3. 目前还存在什么关键瓶颈或争议？
4. 作者提出了什么新的分子设计或合成策略？
5. 作者的研究思路图（Scheme/Graphic）是怎样阐述这个逻辑的？

如果每次阅读新论文时，都要在聊天框中手打这五条要求，不仅繁琐，而且容易遗漏。

**Skill（技能包）就是把一类任务的触发条件、执行步骤、提取标准与输出模板系统化整理后的规程包。**
支持该机制的 Agent 可以按需读取这些规程，使同样的专业标准能够一键复用在新的文献和数据上。

### 5.3.2 技能包怎样组织与按需加载

按照通用的 [Agent Skills 规范](https://agentskills.io/specification)，技能包的核心是一份名为 `SKILL.md` 的 Markdown 说明文件：

![技能说明文件的名称、用途、操作步骤和配套资料](https://clidxhk.github.io/AI4Chem/手册/通用版/图片/第五部分/skill-anatomy.jpg)

*图 5-3　Skill 文件的标准结构。来源：[Anthropic，Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)，原图。*

如图 5-3 所示，一个标准的 Skill 包含以下结构：
- **元数据头部（Frontmatter）**：写明技能名称（`name`）与用途说明（`description`）。这让 Agent 能够“见名知意”，判断当前任务是否需要使用该技能。
- **正文操作步骤（Instructions）**：以清晰的步骤交代先做什么、后做什么、提取哪些核心字段。
- **配套材料（Files/Templates）**：如果操作细节较长（如复杂的提取模板或辅助处理脚本），可以作为子文件存放在技能目录中，供需要时进一步调阅。

Agent 在运行时采用**按需加载（On-demand Loading）**机制：

![应用先读技能简介，收到任务后读取操作说明，再按需读取配套文件](https://clidxhk.github.io/AI4Chem/手册/通用版/图片/第五部分/skill-context-loading.jpg)

*图 5-4　Skill 的按需进入上下文过程。来源：[Anthropic，同上文](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)，原图。*

平时，Agent 的上下文中只保留每个 Skill 的简短名称与描述，占用极少的上下文；
一旦用户交代了匹配的任务（如“帮我按前言规程整理这篇论文”），Agent 才读取对应的 `SKILL.md` 正文；若正文里引用了特定格式表格，系统再进一步调阅配套模板。
这种机制既保证了操作流程的专业规范，又避免了一次性灌入过多说明而挤占上下文窗口。

### 5.3.3 化学科研中的代表性 Skill 场景

技能包非常适合用来承载有明确格式要求和固定质检标准的科研工作：

| 科研任务 | Skill 中需要固定的规程 | 合格产物的验收重点 |
|---|---|---|
| **文献前言结构化笔记** | 明确拆解的 5 个关键问题、提取深度、必须保留的图号 | 每条结论能对应到原文引言段落，不掺杂编造观点 |
| **AIE 文献跟踪卡片** | 固定的提取项：分子结构名、固液发射波长、量子产率、溶剂条件 | 严格保留测量条件，信息不全时明确标出缺失字段 |
| **参考文献格式核验** | 指定期刊的引用风格（如 ACS、Angewandte）、排序规则 | 逐条对照作者、期刊缩写、年份、卷期与页码，指出格式错误 |
| **实验操作规程（SOP）整理** | 步骤顺序、试剂纯度要求、反应温度、安全注意事项 | 对照原始记录核实有无遗漏步骤，关键参数与单位准确 |

### 5.3.4 从一次成功的科研任务提炼出 Skill

编写技能包不需要一开始就从头写一套复杂的规范，最有效的方法是“先实践，再提炼”：

1. **单次打磨跑通**：
   挑选一篇典型的目标文献，以对话的方式引导 Agent 进行整理。中途指出它的遗漏、纠正格式问题，直到产出一份完全符合你心意的文献笔记。
2. **提取固化为规则**：
   让 Agent 把刚才这轮成功交互中你强调的所有要求、字段分类和表格模板总结出来，保存为一份标准的 `SKILL.md`。
3. **换一篇文献检验**：
   拿一篇结构不同的新文献进行试跑，观察规则是否清晰、产物是否稳定，根据试跑结果增补对特殊情况（如文献缺少机理图）的处理指引。

**先有成熟有效的科研做法，再有自动化沉淀的 Skill。**
把个人的好习惯固化下来，就能让 Agent 成为长期遵守你课题组科研规范的稳定助手。

## 5.4 市场：分清模型、底盘与产品

### 5.4.1 从一个实际任务理清三层角色

假设你在 VS Code 中使用 Cline 整理个人学术主页，并生成了一份可以在浏览器中打开的 HTML 简历。
在这个工作中，有三个经常容易被混淆的角色在协同配合：

| 角色 | 它是谁 | 在这个例子中具体负责什么 |
|---|---|---|
| **具体模型（Model）** | 如 DeepSeek-V3、Claude 3.7 Sonnet | **负责思考与生成**：理解你对主页结构的要求，编写 HTML/CSS 代码，判断报错原因 |
| **运行底盘（Harness）** | 围绕模型搭建的执行与调度框架 | **负责动手与管理**：将模型的想法转化为具体的系统操作，读写硬盘文件，记录任务进展 |
| **客户端产品（Client）** | VS Code 及其中的 Cline 界面插件 | **负责交互与展示**：为你提供输入要求的面板，展示文件树与代码差异，弹出权限确认框 |

平时大家常说的“某个 Agent 真好用”，往往是这三者协同工作的综合体验。
理清这三层关系，在选择工具时就能准确判断：当前遇到的问题究竟是模型理解力不足，还是运行底盘缺乏对应工具，抑或是界面操作不顺手。

### 5.4.2 为什么 Agent = Model + Harness

大语言模型本质上只是一套庞大的参数矩阵，它只能“接收输入文本，输出预测文本”，它自己没有眼睛、没有手脚，也没有长久的记忆。

**要把模型变成真正能干活的 Agent，必须给它装上一套运行底盘（Harness）。**

![语言模型在应用中连接检索、工具和记忆等外部能力](https://clidxhk.github.io/AI4Chem/手册/通用版/图片/第五部分/augmented-llm.png)

*图 5-5　围绕模型连接外部能力形成 Agent。来源：[Anthropic，Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)，原图中的 augmented LLM。*

如图 5-5 所示，Harness 扮演了“模型躯干与操作系统”的角色，主要承担四项核心功能：

1. **工具连接与调用（Tools）**：
   当模型在输出中表示“请帮我读取 `spectrum.csv`”时，Harness 负责真正执行系统命令打开该文件，并把文件内容送回模型的上下文。为了让各种外部工具能够标准化接入，业界推出了如 **MCP（Model Context Protocol，模型上下文协议）** 这类统一规范。
2. **任务记忆与状态跟踪（Memory）**：
   在一项包含十篇文献的长任务中，模型单次能看的内容有限。Harness 负责维护任务记事本：记录哪几篇已经处理完毕、当前卡在什么问题、用户的特殊格式要求是什么，确保任务可以跨轮次、跨会话平稳推进。
3. **安全边界与权限控制**：
   模型生成的代码是否安全？是否可以覆写文件？Harness 负责在执行敏感系统操作（如删除文件、提交网络请求）前停下来，向人类用户申请确认，防止误操作。
4. **报错与反馈循环**：
   如果脚本运行报错，Harness 会把错误日志完整捕获并交回模型，支撑模型形成“尝试 → 报错 → 分析原因 → 修正代码 → 再次运行”的自主工作闭环。

### 5.4.4 用化学真实任务检验工具

评测榜单上的跑分通常基于通用基准测试，无法直接等同于它处理你课题组数据的表现。

**检验一个 Agent 工具是否适合自己，最有效的方法是用一项真实的科研小任务跑一遍。**
例如：准备一份包含两组样品发射光谱的真实原始数据表格（含波长、吸光度、发射强度），要求候选工具完成以下工作：
1. 读取该文件并正确解析表头；
2. 编写 Python 脚本绘制两组样品的归一化发射光谱对比图；
3. 输出图表并交付整理后的数据摘要。

在测试过程中，重点关注：
- **数据解析能力**：表头、多列数据、单位与缺失值是否识别正确，有无张冠李戴。
- **排错能力**：绘图脚本初次报错时，它能否根据 Traceback 自主调整并成功画出图像。
- **指令服从度**：对图例名称、坐标轴范围、导出格式（如矢量图 PDF）的细节要求能否准确执行。

跑通手头的真实任务，比看任何榜单排名都更有参考价值。

## 5.5 接入与付费：让应用调用模型服务

### 5.5.1 API 调用的基本过程

在厂商提供的官方网页中聊天时，网页已经为你配置好了一切底层连接。
但当你使用 VS Code 插件（如 Cline）、独立科研工具或自己编写的 Python 脚本时，需要由你指定让哪家模型服务商来提供计算能力。

程序之间进行数据传递与服务调用的标准化约定，称为 **API（Application Programming Interface，应用程序编程接口）**。

一次常规的 API 调用过程非常简单：

1. **组织请求**：客户端应用将你的提问、上下文材料和选定的模型标识打包为规范的请求数据包。
2. **发送鉴权**：客户端向服务商给定的网络地址发送数据，并附带专属的密码凭据（API Key）。
3. **计算返回**：服务商服务器验证凭据有效后，调用目标模型进行计算，将生成的答案以结构化格式返回给客户端。
4. **呈现结果**：客户端解析返回的内容，呈现在屏幕上，或由 Harness 决定执行下一步操作。

### 5.5.2 接入三要素：Base URL、API Key 与 Model ID

无论使用哪款第三方客户端或编程插件，配置模型服务时通常都需要填写以下三项核心配置：

| 配置项 | 通俗含义 | 它告诉程序什么 | 填写与核对要点 |
|---|---|---|---|
| **Base URL** | 服务基础地址 | “请求发给哪台服务器” | 严格按照服务商官方接口文档填写，末尾路径需完整对齐 |
| **API Key** | 访问凭据（密钥） | “是谁在发起调用，费用从谁账上扣” | 相当于账号的消费密码，一旦泄露可能导致额度被盗刷 |
| **Model ID** | 模型具体代号 | “指定服务器上的哪个具体型号干活” | 必须与该服务商当前支持的模型代号清单完全一致（如 `deepseek-chat`） |

![Cline 配置页中分别填写服务地址、被遮蔽的 API Key 和具体模型标识](https://clidxhk.github.io/AI4Chem/手册/通用版/图片/第五部分/cline-provider-settings.png)

*图 5-6　客户端连接模型服务时的配置界面示例。来源：[d.run 官方文档，在 VSCode 和 Cline 中使用](https://docs.d.run/models/user-guides/cline-in-vscode)，原图；旧版界面示例。*

> [!CAUTION]
> **API Key 安全红线**：
> API Key 直接与个人的账户扣费关联。**绝对不要**把 API Key 明文写入代码并提交到公开 GitHub 仓库，也不要在公开交流群中截图展示含有完整 Key 的界面。一旦发生意外泄露，应立即登录服务商控制台注销旧 Key 并重新生成。

### 5.5.3 常见付费方式：订阅、按量与专用套餐

使用现代大语言模型服务，常见的付费方式主要有三类：

1. **官方网页/客户端订阅（Subscription）**：
   按月或按年支付固定费用（如常见的各类 Pro 会员），换取在官方网页或官方应用内的专属功能、高峰期优先保障与日常使用额度。适合主要在官方界面内进行对话、写作和单项查阅的用户。
2. **API 按量付费（Pay-as-you-go）**：
   不预先绑定固定月费，在账户中充值一定金额，后续根据实际处理的内容多少（Token 用量）实时扣费。用多少扣多少，透明灵活，非常适合接入各种第三方插件或自己编写自动化脚本。
3. **Coding Plan 等工具专用套餐**：
   部分云服务商针对高频使用编程与 Agent 工具的场景推出的定制套餐。通常按周期收取固定费用，并在支持的工具列表内提供较为充裕的调用配额。

### 5.5.4 为什么问一句话会消耗很多资源？

在聊天框中问一句话，AI 只回答一次；但在 Agent 辅助科研时，很多初学者会困惑：“为什么我就让它帮我画个图，后台却显示消耗了这么多额度？”

理解这个现象，需要厘清两个底层概念：

**1. 计量单位 Token（词元）**
模型处理文本时，不是按“字”或“词”整块读入，而是把文本切分成一小段一小段的片元，称为 **Token**。
- 输入给模型的材料折算为**输入 Token**（Input Tokens）；
- 模型自己生成的文字折算为**输出 Token**（Output Tokens）。
- 服务商按量计费时，正是根据这两者的数量来结算费用的（通常输入 Token 比输出 Token 更便宜）。
- 这就像在打印店复印材料：你印一页提问和附带印一整本 50 页的文献附录，消耗的纸张和费用完全不同。

**2. 一次提问 ≠ 一次模型调用**
当你给 Agent 下达一个指令：“阅读这个目录下的光谱数据，画出对比图，如果有错就改好。”
在完成这项任务的过程中，Agent 背后实际上经历了多次往返循环：
- 第一次调用：模型阅读任务指令，决定“查看目录文件”（输入少量，输出少量）；
- 第二次调用：Harness 读取了数千行的数据文件交回模型，模型理解数据并编写 Python 绘图代码（**输入骤增**数千 Token，输出代码数百 Token）；
- 第三次调用：脚本在本地运行报错，Harness 把整段报错堆栈送回模型，模型重新分析错误并给出修复方案；
- 第四次调用：代码运行成功，模型查看输出图片确认无误，交付结果。

**用户在界面上只下达了一次命令，后台却进行了 4 轮调用，且后续每一轮调用都携带了前面的数据与执行历史。**
理解了这个机制，就能明白为什么 Agent 能解决复杂任务，同时在面对大规模数据时，也要合理规划上下文，避免无效的文件灌入导致资源浪费。

### 5.5.5 数据安全的两条核验底线

化学科研数据往往涉及未发表的研究成果、专利结构或与合作企业签订的保密协议。
在使用外部模型服务时，研究者必须守住两条数据安全底线：

1. **确认输入数据是否会被用作模型训练**：
   查阅所选模型服务商的 API 隐私条款。正规云服务商与模型厂商的商用 API 接口，通常明确承诺**“通过 API 传输的用户数据默认不用于模型迭代训练”**；而部分免费的网页版对话产品，默认协议中可能会包含允许将对话数据用于算法改进的条款。涉及重要课题资料时，优先选用商业 API 通道。
2. **确认是否符合课题组与机构的保密要求**：
   涉及敏感化合物合成路线、未公开专利的核心骨架或未解密的数据，须严格遵守所在单位的知识产权与数据出境规范。涉及高度涉密的数据，应选用内网隔离环境或本地私有化部署的模型方案。

## 5.6 本章小结

1. **从 ChatBot 到 Agent，核心是从“被动对话”走向“自主推进任务”。** Agent 以大语言模型为判断核心，通过工具调用与环境反馈形成“判断—行动—反馈—再判断”的闭环，在明确目标下独立执行多步工作。
2. **上下文是模型眼前的参考书，RAG 是自动查找参考书的机制。** 模型本身不掌握私有最新数据；通过检索增强生成（RAG），应用先在本地或数据库中检索相关片段补入上下文，再由模型据此给出有据可查的回答。
3. **化学事实提取必须将数值、测量条件与原文位置绑定。** 脱离了聚集状态、溶剂、浓度与测试波长的光谱数值没有科学意义；人工核对结论时，紧抓“出处在哪里、原文哪句支持、测试条件是否对齐”三项核心。
4. **Skill 是沉淀个人科研习惯的规范包。** 它是可复用的“操作方法说明书”，通过元数据描述实现按需动态加载；从一次成功的手动交互中提炼出稳定的提示词、提取字段与输出模板，即可沉淀为长期复用的专业技能包。
5. **分清“具体模型（Model）- 运行底盘（Harness）- 交互界面（Client）”三层关系。** 模型负责思考，底盘负责管理工具、任务记忆与执行反馈；检验一款 Agent 工具，最好的方式是用课题组手头真实的数据跑通一次清洗、分析与绘图。
6. **API 是外部工具调用模型的标准通道，一次任务可能产生多次调用与 Token 消耗。** 正确配置 Base URL、API Key 与 Model ID 即可建立连接；清楚 Token 计量原理与自主循环机制，守住数据隐私安全底线，才能在日常科研中稳定高效地用好 AI 工具。

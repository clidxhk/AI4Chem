# 第三部分：数据和信息——AI 的燃料从哪里来

# 引言

如果你是做化学、材料或生物实验的研究者，下面这些场景大概不陌生：

- 实验记录本记得密密麻麻，真要找"当时用什么浓度、什么温度测的"，却要翻半天；
- 想把手头的文献整理成一份能用的数据表，发现数据全埋在正文和图片里；
- 听说"数据是 AI 的燃料"，却说不清自己的数据到底算不算好。

先停下来想一个最基础的问题：**你的实验记录本，在计算机眼里是什么？**

上一章说过，计算机只会按规则处理 0 和 1，并不"理解"什么。那么：波长、产率、谱图、分子结构……这些五花八门的科研数据，是怎么变成 0 和 1 的？反过来，一堆 0 和 1 又怎么变成"信息"，甚至"知识"？要提醒的是：预测效果的上限，往往在数据集建好的那一刻就已经决定了。

本章回答五个问题：

1. **概念**：什么是数据？什么是信息？它们是什么关系？什么算知识？
2. **表示**：数据的类型有哪些？文字、数字、图片、分子结构在计算机里分别是怎么表示的？
3. **结构化与非结构化**：两者有什么区别？你的科研数据各属于哪一类？
4. **标准**：什么样的数据才算"好数据"？"多"和"好"哪个更重要？
5. **文献数据与机器学习**：文献里的数据为什么经常"不好用"？机器要"学出规律"，数据至少需要什么条件？

## 3.1 概念：数据、信息与知识

### 3.1.1 数据是原始记录，信息是解释结果

先给出一组够用的定义：

**数据是对事物状态的原始记录**——数字、文字、符号、图像、声音，尚未被解释；**信息是数据被放入语境、经过整理和解释之后产生的产物**，能够消除不确定性、对接收者产生明确意义。

一句话概括两者的关系：**数据是信息的载体和基础，信息是数据的加工结果；数据 raw、含义未明，信息有序、有价值。**

这个定义可以追溯到香农的信息论：**信息是减少（消除）不确定性的量**。它诞生于一个很实际的工程背景——20 世纪初电报电话按字收费，信息传播昂贵，人们必须精确地度量"一条消息到底传了多少东西"。

> **体温计上的 37.2**
> "37.2"是数据，"这个人发烧了"是信息。差别不在数字，而在**参照系与解释**。
>
> "数据是载体，信息是数据的解释结果，不是数据本身的属性。同一份数据在不同语境下给出不同的信息——没有语境的数据就是噪声。"（匿名摘录）

落到科研里，"数据 → 信息"的转化随处可见：

| 场景 | 数据（原始记录） | 信息（解释结果） |
|---|---|---|
| 荧光表征 | 不同水含量下的荧光光谱强度（如水含量 90% 时 605 nm 处强度 1847 a.u.） | 该分子具有典型聚集诱导发光特性：聚集后荧光显著增强，发射峰随之红移 |
| 光热实验 | 808 nm 激光、1.0 W/cm² 照射 5 min 后的孔板吸光度读数 0.62 | 该功率密度下细胞存活率约 55%，光热有效，但需评估暗毒性 |
| 紫外定量 | 分光光度计在 595 nm 处的原始吸光度 0.582 | 结合标准曲线，样品浓度为 0.45 mg/mL |
| 反应控温 | 三次温度读数 25.6、26.1、25.8 | 平均温度 25.8 ℃，波动 ≤0.3 ℃，满足实验可控条件 |
| 文献对照 | 文献记录"实验组转化率 32.5%，对照组 18.2%" | 该处理方法可显著提升转化率，幅度达 14.3% |
| 动物实验 | 每次治疗后测量的肿瘤体积 | 整个疗程的体积变化趋势，说明治疗是否真的有效 |
| 光谱对比 | 同一样品溶液与薄膜的发射峰 450 nm 和 510 nm | 从溶液到薄膜，发射峰红移了 60 nm——但还不能证明红移由哪种机制引起 |

注意最后一列的"边界"：I = 1847 a.u. 本身什么也没说，只有放进"溶剂体系 / 浓度 / 激发波长 / 仪器参数 / 对照组"之后，它才变成信息；"红移了 60 nm"也还不能证明红移的机制。

还有一个容易忽略的点：**数据与信息是相对于使用场景而言的，并非两种永远互斥的东西**。"红移了 60 nm"这条提取出的信息，保存进另一张表之后，对下一个问题来说又成了数据。

### 3.1.2 信息离不开目的与劳动

除了信息科学的定义，"信息"在管理学里被看作**组织劳动生产的核心驱动力**；在经济学里，数据已是重要的生产要素——数据能成为资源，甚至被交易。

对"数据是什么"，一个有启发性的理解是：**数据是人与物质的量，以及人与人、人与物、物与物之间关系的总和，能够被数字化的形式固定下来**。几个苹果是量，看了多长时间手机是人与物之间关系的量——这些量连同文字信息（先变成 token、再变成数字）一起，构成"计算机的燃料"。

而信息一定包含**整理与目的**。如果单看数据而没有目的，里面其实没有信息——"这里有几个苹果"这个数据的目的在于指出苹果的数量；没有目的，信息就不存在。

一个例子：**"我做了五个反应"，写在实验记录本上是一个数据；向别人汇报"我今天做了五个反应"，就包含了一定的信息量——它反映了你的劳动投入。**同一行字，语境不同，信息量不同。

### 3.1.3 从数据到智慧：DIKW 分层

管理学中常见的 **DIKW 分层**把认识过程分成四级：数据（Data）→ 信息（Information）→ 知识（Knowledge）→ 智慧（Wisdom）。艾略特的诗句问的正是这层层递进中的失落："我们在信息中失去的知识在哪里？我们在知识中失去的智慧在哪里？"

本章主要把"数据 → 信息"这一级讲清楚；知识与智慧两级，值得在实践中有了更多积累再回头看。

**注意：仅把大量文件放进电脑，并不会自动产生可靠的知识。**物理上，计算机运行需要电能；计算任务需要程序与输入。机器学习把数据当作学习材料，由算法调整模型参数，并消耗算力——燃料本身不等于发动机。

## 3.2 表示：一切如何变成 0 和 1

### 3.2.1 数据的类型：同一个东西可以同时属于好几类

数据分类没有唯一答案，取决于分类角度，而几个角度可以同时成立：

| 分类角度 | 常见类型 | 科研例子 |
|---|---|---|
| 按统计含义 | 数值型 / 类别型 | 收率、温度；溶剂类别、催化剂种类 |
| 按内容形式 | 文本、图像、音频、视频、序列、图结构等 | 实验描述、显微照片、光谱序列、分子连接图 |
| 按组织方式 | 结构化、半结构化、非结构化 | 实验表格、JSON 记录、自由书写的讨论 |

按数据性质还可以细分为定量数据（离散型：细胞计数；连续型：温度、体重）与定性数据（类别数据：血型；顺序数据：满意度等级）；编程语言中有基本类型（整数、浮点、字符、布尔）与复合类型（数组、列表、字典、对象）之分；按来源与时效又分静态数据与流数据。其中"按结构化程度划分"最常用——这正好引出下一节。

**注意：类别即使编码成数字，也不一定有大小关系。**用 1 表示 THF、2 表示 DCM，不意味着 DCM 是 THF 的"两倍"。

科研中常见的数据类型可以铺成一张表：

| 类型 | 说明 | 例子 |
|---|---|---|
| 标称（名义） | 只有类别，无顺序 | 分子类别、细胞系名称 |
| 序数 | 有顺序，间距不确定 | 染色强度 + / ++ / +++ |
| 数值·离散 | 可数 | 细胞计数、PCR 循环数 |
| 数值·连续 | 可测，精度受仪器限制 | 波长、OD 值、温度 |
| 文本 | 自然语言 | 论文、实验笔记 |
| 图像 / 信号 | 二维或一维阵列 | 显微图、光谱曲线 |
| 图 / 结构 | 节点加边 | 分子图、相互作用网络 |

### 3.2.2 数字、文字、图片：三种基本编码

计算机无法直接识别文字、图像等内容，一切数据都要转换为二进制 0/1 编码存储和运算，靠的是**约定一套抽象映射规则**。这套约定是双向的：编码规则规定如何把文字、数值转换成位串，软件再按同样的规则解析——**写进去和读出来必须用同一套规则**。

**数字**：整数直接逢二进一（十进制 5 = 二进制 101，即 1×2²+0×2¹+1×2⁰）；负数用补码，最高位表示正负；小数用 IEEE 754 浮点标准，分成符号位、指数位、尾数位三段存储。

但位数是有限的：**n 位二进制只能表示 2 的 n 次方个不同值，精度有上限**——很多小数只能近似表示。上一章讲过的 Ariane 5 火箭事故，根源正是精度上限：一个数值从 64 位浮点转 16 位整数时溢出。

**注意：数值 13 和文本"13"的存储含义不同。**

**文字**：通过编码表查表。ASCII 给每个英文字符规定一个数字——'A' 对应十进制 65，存为二进制 01000001；ASCII 只有 128 个位置，表示不了汉字，于是 Unicode 给世界上每一个文字符号（甚至 Emoji）分配唯一编号（汉字"中"是 U+4E2D），再通过 UTF-8 等变长规则转成字节序列。

**注意：中文是按编码规则存储的，不是先变成图片。**

**图片**：位图把图片打散成像素网格，每个像素用数字记录颜色。任何颜色都可由红绿蓝三原色混合而成，每种原色用 0–255（8 位二进制）表示强度——纯红色像素记作 (255, 0, 0)，即二进制 11111111 00000000 00000000；一张 1920×1080 的图片，就是把两百多万个像素的色彩数据按从左到右、从上到下的顺序串成一长串 0 和 1。灰度图单通道，显微图常用 16 位色深。矢量图（SVG 等）不存像素、存数学公式（绘图描述）。宽、高、色深和压缩方式都影响文件。

**光谱 / 声音**：连续信号经离散采样加量化变成数字序列，采样率与位深决定保真度。

### 3.2.3 分子结构：不是存"图"，而是存编码

对化学人来说最关键的问题是：分子结构怎么存进计算机？答案是——**不是存"图"，而是存编码**：

| 表示方式 | 怎么存 | 特点 |
|---|---|---|
| SMILES 字符串 | 一行特定字符表达分子拓扑，如乙醇 CCO、水 O | 可再经 UTF-8/ASCII 转为 0/1；同一个分子可有不止一种有效写法 |
| InChI / 分子指纹 | 标准化标识符 / 位向量 | 指纹是常用的数值化表示 |
| MOL 文件 | 原子坐标 + 键连表 | 完整描述还需立体化学、电荷等字段 |
| PDB 格式 | 原子列表 + 3D 坐标 (X,Y,Z) + 连接关系表 | 生物计算、药物筛选常用 |
| 分子图（图神经网络） | 原子是节点、化学键是边，节点与边的属性写成矩阵，最终转为浮点数 | AI 领域的表示法 |
| 结构式截图 | 像素 | 主要记录像素，程序难以直接读取结构与连接关系 |

统一点：**一切都经过离散化 + 编码，变成一个数字序列。代价是连续世界只能被近似，精度永远有天花板。**

现有表示方法还有几条重要的边界：

1. **同一个分子不止一个有效的 SMILES 写法**；普通 SMILES 不等于唯一编号，也不会自动包含三维构象——不同写法对应的三维构象也不一样；
2. **对聚合物，仅一个重复单元不能完整说明链长分布、序列、端基和样品状态**。人类目前对聚合物的信息表达方式本身也说不清这些问题——链长用重复单元数或分子量表示，固体形态用一套自然语言描述；
3. **刺激响应结构、纳米粒子等复杂体系的表述维度更不够**：这类研究常用光谱变化来表征刺激响应，但光谱表达也不够——"这次做的纳米粒子和那次做的纳米粒子，差异度有多大"都规定不了。根子在于：人类对这些对象本身的认知层次就没那么高，设定的观察标准就不够准确。

**SMILES 为什么成了主流？**一是**生态**——围绕 SMILES 有很多现成的程序包；二是**信息量**——SMILES 包含原子之间的连接关系（比如碳氮键），而图片转成像素点后这些关系就没了；更进一步，SMILES 还可以用来写化学反应（A 加 B 生成 C）。化学是生成新物质的东西，能表达反应的表示法才好用——"图片的话，你怎么让 A 和 B 叠在一起呢？"

**"键"其实不在原子里。**一个对理解"分子表示"很有冲击力的细节：量化计算文件（如 Gaussian 的输入输出）里，键长键角是程序**按内置规则自动加上去的**——因为在原子层面是没有"键"的；从量子化学角度看，所谓成键就是两团电子云互相重叠。"键"是人类后来加的抽象。我们以为最自然的化学概念，在数据层面都是约定与抽象。

顺带一提，聚合物的计算也受制于表示与算力：目前做法是取几个重复单元做仿真模拟、看构象——上百个重复单元（每个几百分子量）原子数已经不少，优化构象非常耗时。这也是为什么蛋白结构预测会成为 AI 的大领域——AlphaFold 正是借助进化上的相关信息来理解蛋白质折叠的。

### 3.2.4 从物质到比特：层层转递的缺失

面对"纳米粒子怎么表示"这类困境，可以把问题抽象一层：从物质到数字，中间要经过好几层——**物质 → 理论框架 → 计算机**。

这相当于信息的层层转递，**每次转递之间都有信息缺失**。一开始对信息的描述准确度就不够，转到后面缺失度只会更高——就像一张图片不停地复制、转码，最后准确度和像素都会大范围降低。

那怎么办？务实的出路是**化繁为简、只盯目标**：如果要优化的只是一个特征——比如"光谱要达到近红外多少以上"——那就只把与它主要相关的变量（比如共轭长度）抓住，别的都不管，一对一批量优化这几个条件。本质是**构建一个"人类已经确定的物理量"与"你要的最终物理量"之间的关系**。

这个思路，正是下一章"特征与标签"的入口。

## 3.3 结构化与非结构化

### 3.3.1 有没有"形状"，决定好不好用

- **结构化数据**：有预定义模型（schema），固定格式、行列分明、字段类型确定——电子表格、数据库表、CSV、关系型数据库（MySQL、Oracle）；
- **半结构化数据**：不遵循严格的表格结构，但用键、标签或层级表达关系，不同记录的字段可以不同——JSON、XML、HTML、YAML，以及带元数据的仪器导出文件；
- **非结构化数据**：没有预定义数据模型——论文 PDF、手写记录、显微原始图、自由文本、音视频。这类数据占现实世界数据的 80% 以上。

一个直接的判断法：**能不能不读内容、直接按字段名查询和统计？能 → 结构化；不能 → 非结构化。**

**注意：不要仅凭文件后缀判断结构化程度；Excel 中粘满截图，并不会因此成为可直接统计的实验数据库。**

在科研中，两类数据总是并存且互相结合：实验记录里加了多少样、用了什么温度、培养了多久，是明确的、可统计的参数；拍的照片、录的视频、自由书写的文字，则需要二次处理。而且结构化与非结构化数据都有好坏之分——**非结构化数据只要本身准确，经过二次处理就可以变成可用的结构化数据**。

### 3.3.2 科研数据盘点：从表格到照片

把一个典型课题组的资料摆出来，结论几乎总是一样的：两类并存。常见的归类与"转为可分析数据的关键"如下：

| 科研资料 | 通常如何归类 | 转为可分析数据的关键 |
|---|---|---|
| 逐次实验条件与收率表 | 结构化 | 一行一次实验；单位明确；同一列含义一致 |
| UV、PL、GPC 的数值导出文件 | 有明确列定义时属结构化 | 保存横纵坐标及单位，并关联样品与测试条件 |
| 光谱截图、显微照片、薄膜照片 | 通常属非结构化 | 保留原始文件；补充拍摄条件、标尺和样品编号 |
| 自由书写的实验记录、论文正文 | 非结构化 | 提取样品、条件和结果；保留原文便于核对 |
| 带命名字段的 JSON 仪器记录 | 半结构化 | 说明每个字段含义、单位、允许值及缺失规则 |
| 分子连接表、规范的结构文件 | 有明确结构规则的化学数据 | 明确结构身份、立体信息，并与实验记录对应 |

更多例子：结构化一侧还有 96 孔板读数表（孔位/分组/浓度/OD/存活率）、光谱峰值表、化合物库 CSV（SMILES+分子量+logP）、文献计量表；半结构化一侧还有文献管理软件的条目（RIS）、带元数据的仪器原始文件、NMR 的 FID+参数头、CIF；非结构化一侧还有荧光与共聚焦显微图、TEM 图、手写实验记录本、组会 PPT 与研讨笔记。

### 3.3.3 把整理劳动放在日常：一次实验一条记录

有一个可以直接照做的方案：**给每次独立实验一个唯一编号，用它连接条件表、原始光谱与处理结果**；一次实验可以对应多份文件，不必把所有内容强行塞进一个单元格：

| 实验编号 | 溶剂 | 温度/℃ | 时间/h | 分离收率/% |
|---|---|---|---|---|
| R001 | THF | 25 | 12 | 42 |
| R002 | THF | 50 | 12 | 68 |

（简化假设示例。实际记录还需底物结构、投料量、浓度、催化剂、气氛、批次及原始文件位置。）

整理原则：**一列一种含义；单位统一；尽量不合并单元格；样品编号保持一致。**

**注意：未测收率应记为"未测"，不能填 0——0% 是测量结果，和缺失值不是一回事。**

对个人或小课题组，把数据结构化有两条路线：

1. **日常积累**：从现在开始结构化管理——每天下载的文献 PDF 按日期编码、放进固定的文件夹；记录包含日期与来源，条件尽可能统一，单位也统一。一个可操作的做法是按关键词每日检索、手动下载（自动爬虫容易被封，靠平常读文献时随手下载归档），日积月累就能攒下一个数千篇规模的专题文献库；
2. **集中突击**：如果突然来了一个目标明确的任务，就花几个月专门的时间（或者雇人、用技术手段）把大量数据补齐。

两条路线背后是一个清醒的认知：**计算机并不能减少劳动，它只是把劳动转换到了不同的地方、不同的时间上去了。**

## 3.4 标准：什么样的数据才算好数据

### 3.4.1 可操作的标准清单

把各家的清单合并起来，可以得到一套直接对照检查的标准：

| 标准 | 要点 | 科研中怎么检查 |
|---|---|---|
| 准确可信 | 仪器经过校准，有空白与对照，有重复；无篡改、无错误记录 | 单位或抄录有无错误？保留原始记录了吗？ |
| 关键内容完整 | 关键元数据不缺：浓度、溶剂、温度、激发波长、狭缝、仪器型号、测试方法 | 样品身份、浓度、状态、测量方法是否齐全？ |
| 一致可比较 | 单位统一、命名统一、批次可比；方法差异可识别 | 分离收率与核磁收率是否区分？溶液和薄膜是否混在一起？ |
| 覆盖目标范围 | 包含将来要预测的对象和变化 | 是否只测一种底物、一种溶剂或全是高收率实验？ |
| 可追溯可复核 | 谁、何时、哪台仪器、原始文件在哪、经过哪些处理步骤 | 哪个批次、谁测的、怎样扣背景、是否删除过点？ |
| 不确定性明确 | 记录独立重复、误差与检测限；区分未测和未检出 | 测量有多稳定、哪里未知？ |
| 可读取可复用 | 格式开放、许可清晰、有数据字典说明每个字段；别人用你的数据也能画出类似的图 | 能否获得原始数值、字段说明、通用格式和使用条件？ |
| 可查找可访问 | 有唯一标识（如 DOI），存放在稳定位置 | — |
| 适合具体任务 | 对观察峰位趋势足够的数据，不一定足以比较绝对发光强度 | 好数据首先要适合任务 |
| 干净无冗余 | 无重复、无异常噪声、无无效数据 | 冗余与噪声会伪装成规律 |
| 时效性 | 贴合当下研究场景与实验条件 | — |

"一致"这一条有个形象的反例：**不能一个测吸光度、一个测透射率，还有人自己去换算**——单位要一致、命名要一致。

两个重要的配套概念：

- **元数据**（metadata）：是在说明数据的来龙去脉。"发射峰 480 nm"是结果；样品编号、溶剂、浓度、激发波长、狭缝、温度、日期和处理方法，是帮助解释结果的元数据。**没有这些说明，两个 480 nm 也未必可直接比较**；
- **FAIR 原则**：科研数据管理中常用的框架——可发现（Findable）、可访问（Accessible）、可互操作（Interoperable）、可复用（Reusable）。它强调人和机器都能找到并理解数据。

**注意：FAIR 不等于全部免费公开，也不保证实验本身准确。**

### 3.4.2 "多"和"好"哪个更重要

答案是：**好更重要**。

> "脏数据的危险在于它不报错——它会系统性地把结论带偏，而你从结果上看不出来。"（匿名摘录）

理由可以展开成几条：

- 数据再多，如果条件是混乱的，结论就会被带偏——数据被污染了。很多人不给你条件、直接给结果，你用这些结果时会默认一个前提条件，结果就把实际应用带偏。**就算数据少，也得先把数据洗干净：在同样的前提条件下得到一个结论，然后再去扩充**；
- 模型学的是条件与结果的映射，条件里的噪声一大，学到的就是假规律。经验法则：**先保证 200 条干净、元数据完整的数据，再谈 20 万条**——小数据加严格条件，胜过大数据加混乱条件；
- 错误标注、系统性偏差和缺失条件不会因数量增加而自动消失。一个对比：1,000 条来自同一底物同一条件的记录，和 100 条覆盖不同底物与温度的记录——前者适合估计该条件下的波动，后者才可能支持学习跨底物、跨温度的关系。**不能脱离目标，仅凭条数判断价值**；
- 把同一条数据复制 100 次，与做 100 次独立实验完全不同——复制不增加独立证据。

还有一个有意思的类比：人的科研能力是随着经验与积累逐步提高的，经验之于人，正如数据之于 AI——没有好数据去训练，AI 就不会迭代出让人满意的结果。

不过，"好"本身还需要再补一个定义：**尽可能囊括要描述的目标的搜索空间，有代表性**；在这个前提下，数据要尽可能多。给一座山做等高线图，如果采样点踩得很好但网格太宽，就会丢掉大量细节——丢掉的细节严重时能"把一座山变成一个盆地"。另一个直观的比喻是屏幕分辨率：480P 能看出是个人，4K 下面连头发丝都看得清。

这里藏着化学的现实困境：**目前对化学来说最难的地方是数据都不够。**即使一个深耕 20 年、积累了上万分子的领域，相对要搜索的问题空间仍然很不充足。

怎么判断手头一份数据是好是坏？答案的第一步不是找清单，而是**先定义你的目标**——在目标确定之后，再逐条对照上面的标准，外加"尽可能布满整个空间"这一条。

## 3.5 文献数据与机器学习的门槛

### 3.5.1 文献里的数据为什么经常"不好用"

两个领域的切身经验很有代表性：

- **生物领域**：细胞实验、动物实验受外界干扰很大——不同人的培养方式、操作方式、甚至加样方式不一样，都会导致结果不稳定；有的实验有概率重复不出来。有些文献为了保护自己的研究经验，会**隐藏关键操作细节**；还有些作者会**挑选自己满意的数据**，导致结果不可靠；
- **合成领域**：作者实际的条件变了，但在实验部分换了一种方式描写，照着文献的方法可能合不出相关分子。

综合起来，"文献数据不好用"的原因可以归成六类：

1. **只报结论，不报原始值**——给 IC50 却不给剂量–反应原始数据；说"增强 20 倍"却不给绝对量子产率与参比标准；
2. **条件缺失**——溶剂、浓度、激发波长、狭缝、温度、仪器型号常不完整，导致跨文献不可比；
3. **单位与定义不统一**——同一物理量有时用相对倍数、有时用绝对量；"存活率"的归一方式各家不同；产率有写 0.几 的、有写百分号的；
4. **选择性报告（发表偏倚）**——只发表好看的结果，阴性数据不发表，数据本身带系统性偏差；
5. **数据锁在图片里**——曲线以像素形式躺在 PDF 中，只能人工读数，引入数字化误差；
6. **批次效应**——细胞代次、染料纯度、光照剂量的差异使复现困难。

> "文献里的数据是为了说服审稿人而组织的，不是为了被机器消费而组织的。"（匿名摘录）

关于第 4 条，为什么不发表负面结果？除了"正结果更容易发表"的导向，也有研究者的现实考量：完整的实验记录（包括失败尝试）是长期积累的经验与技术路线，全部公开相当于交出多年劳动；负结果往往留作内部参考，或用来做对照。这不是个别人的问题，而是整个发表生态的现状——但对想用文献数据训练模型的人来说，它意味着**很大一部分数据空间被系统性省略掉了**。

一个补充线索：论文打假大多发生在要求上传原始数据的子刊——从原始数据里能查到线索；多数化学期刊并不要求上传原始数据。而有的大型出版系列早在十年前就逐步完善了原始数据上传制度。

结构化学还有一个都有体感的痛点：单晶结构虽然自带坐标，但 **CIF 文件里的化合物名和文章里实际的分子简写往往对不上**——用本章的话说，这个信息不是结构化的、不是一一对应的，你得先付出很大劳动去找、去核对。而且单晶结构反映的是固体结晶状态下的构象，并不一定是液体中的状态。

### 3.5.2 从文献里"挖"数据：成本、工具与 AI 的角色

文献数据既然锁在文字和图片里，获取它就是一门苦力活：

- 数据埋在大量**需要领域知识**的文字里——不懂这个方向的人，连图都看不懂；熟悉的人找一张图也要一两分钟。文献天然不是为了让人提取数据而写的，它主要是为了传达设计思路和理念；
- 人工提取成本很高：甚至出现过按条计价的人工数据提取服务，即便如此也未必有人接单——纯耗时间。按"十分钟找一条"估算，一天 8 小时也就 48 条；经常看完一整篇文献才能找到一条，还得把补充材料下载下来。这活儿"本科生可能都不太够，说不定还得雇个硕士"；
- **程序辅助**：可以用 Python 对文本扒关键词，大模型进来之后成本又低了一些。但要分清层级：关键词级别的提取没问题，**越是抽象、越是框架性的判断，大模型就越不好使**。

一个真实案例：用 AI 知识库工具接上一个数千篇文献的专题库，检索"808 nm 激光光热治疗常用功率"，从三千多篇里自动筛出 54 篇相关文献并列出功率记录。结果暴露了三个问题：

1. **结果不全**——检索的限定条件加多了，几千篇里只抓出 54 篇；
2. **记录五花八门**——功率有写范围的、有带斜杠的，单位各不相同，很难统一（不同仪器厂家还不一样）；
3. **AI 会出错**——大模型存在事实性偏差（幻觉），筛出来的值需要回到对应文献里核实。

结论是：**靠 AI 挑出来的数据之后还要再去核实，这也是一个很花时间的地方**；但整体上仍然值得——人工看不一定能看这么多文献。

这里顺带补一课 **RAG（检索增强生成）**的原理。所谓"库里的全文搜索"，并不是把整篇文章都塞给大模型（一篇文章几千字，token 消耗太大）；而是先把库里的每段内容转换成一段数字（向量），把你的问题也转换成数字，按数学上的相似度比对，把最接近的段落抽出来，和你的问题一起发给大模型——这样模型的回答就会非常接近原文。

对"AI 挖数据到底靠不靠谱"，一个务实的回答是：**初步筛选肯定比没有强**——以前构建一个数据库要一个人不断积累一年多，现在成本已经明显下降；大模型总会有幻觉，但即便如此，"至少比人工洗强很多"。洗过数据的人都懂这种痛苦，AI 的帮助是真实的。本地部署模型或调用 API，都可以做这类提取（识别关键词、识别分子结构式）。

### 3.5.3 机器要"学出规律"，数据至少需要什么条件

一个自然的疑问是：**训练数据所需的逻辑关系，是先天的还是后天的？**

最基本的要求是先天的：**输入和输出要先建立对应**——比如激发波长与发射波长，先把对应关系建立起来，再去找规律。

更抽象、更框架性的逻辑，则可以后天赋予：生物信息学里大量"先统计出关联、再赋予机理解释"的工作就是先例；一段合成最终有一个产率，不管写成 0.几 还是百分号，先天确实有东西——更高层次的统一与抽象（统一成百分号或小数）是后来完成的。从零开始不太可能，一定是先有一点东西。

概括起来：**数据先天至少要具备"输入–输出对应"这一最低层次的结构；框架性的逻辑可以事后整理与赋予——但整理的前提是先天有东西可整理。**

更完整的"最低条件"清单，以预测反应收率为例：

| 最低条件 | 以预测反应收率为例 |
|---|---|
| 映射真实存在 | 输入 X 与输出 y 之间确有稳定的对应关系，而不是随机 |
| 关键变量必须在输入里 | 提供底物、催化剂、溶剂、温度等；缺了决定 y 的变量就永远学不会——不记录光功率密度，就学不出光热规律 |
| 记录与目标正确对应 | 结构、条件和收率属于同一次实验；标签定义一致，缺失有说明 |
| 有足够独立的变化与覆盖 | 覆盖相关底物、条件和低收率结果；样本量取决于任务，没有统一最低条数 |
| 标注一致、噪声可控 | 标签定义必须明确（"存活"的阈值到底是多少）；记录重复与波动 |
| 分布一致 | 训练与预测来自同一分布；跨批次、跨仪器必须校正 |
| 留出验证集 | 才能区分"学到了规律"和"背住了答案" |

这里提前出现几个下一章的关键词：**特征**（输入描述）、**标签**（希望预测的答案）；**数据泄漏**——不要让测试答案或预测时无法获得的信息参与训练，否则模型看起来很准却无法预测新实验；**无监督学习**不要求人工标签，**自监督学习**可从数据本身构造目标，但它们同样需要质量与覆盖，而且**学到相关性不等于证明因果机制**。一句话概括：数据要符合最终目标的需要，真实、数量多、信息量高、分布广泛——**能够描绘目标函数的空间**。

**几十条数据能不能直接搭库训练？**答案是**看目标**——先定义目标，再按目标难度评估需要多大数据量、最后要达到什么精度。

**化学的数据从哪来？**先算一笔账：自己做样本，按最保守的估计，一个样本仅材料成本就要几十元，还没算人力。作为参照，AI 制药领域拿数据有两条路：一是**从头模拟**——先通过大量理论计算或分子模拟，再随机生成一大批分子去"合理碰撞"看能不能接上，然后筛选；二是**存量积累**——多年的合成实践本身就积累了大量结构化数据。第三种是**高通量筛选**，一次做很多样。高通量筛选是否值得投入，还取决于学科的产出结构：如果中间产物在各个阶段都有独立价值，投入就容易持续；如果只有唯一最优结果才有价值，失败风险就很高。

## 本章小结

1. **数据与信息的分界在语境与解释**：数据是对事物状态的原始记录，信息是数据被放入语境、整理和解释后消除不确定性的产物；数据是载体，信息是解释结果——没有语境的数据就是噪声。两者相对使用场景而言并不互斥：一条提取出的"信息"存进表格后，对下一个问题来说又是数据；
2. **一切皆 0/1，靠的是约定编码**：数字（二进制、补码、IEEE 754）、文字（ASCII → Unicode/UTF-8）、图像（像素网格 + RGB）、光谱（采样 + 量化）、分子结构（SMILES、MOL、PDB、分子图）都经过离散化 + 编码变成数字序列；代价是连续世界只能被近似，n 位编码的精度永远有天花板；
3. **分子表示是化学人的特殊一课**：分子结构不是存"图"而是存编码；SMILES 成为主流靠的是生态与信息量（能表达连接关系与反应）；"键"在原子层面并不存在，是程序按内置规则加上的人类抽象；同一分子有多个有效 SMILES 且不自带构象，聚合物的链长、序列、构象尚无好的数字表示——复杂体系表示维度的不足，根子在于人类认知与观察标准本身不够准确。从物质到理论框架再到计算机，层层转递、层层缺失；务实的出路是固定目标、只抓与目标物理量相关的主要变量；
4. **结构化与否看"能不能按字段查询"**：结构化（schema）、半结构化（JSON/XML/CIF）、非结构化（PDF/图片/手写）三分；科研数据两者并存且互相结合，非结构化数据只要本身准确，经二次处理可变成结构化。好习惯是把一次实验整理成一条记录：唯一实验编号 + 完整元数据 + "未测≠0"，把整理劳动放在日常——计算机不减少劳动，只是把劳动转移了时间和地点；
5. **好数据有可操作的标准**：准确、完整、一致、可追溯、不确定性明确、可复用、可查找可访问（FAIR），再加上两条化学语境的关键项——适合具体任务、覆盖目标搜索空间。"多"与"好"的共识是先好再多：脏数据不报错，会系统性把结论带偏；而"好"的完备定义包含对搜索空间的代表性覆盖——这对数据普遍偏少的化学尤其重要；
6. **文献数据不好用，因为它是为人组织的，不是为机器组织的**：只报结论不报原始值、条件缺失、单位不统一、选择性报告（负面数据缺失）、数据锁在图片里、批次效应，是六大系统性原因。AI（RAG 检索 + 大模型初筛）大幅降低了挖数据的成本，但筛出的数据仍需人工核实，越是框架性的判断 AI 越不好使；机器学习对数据的最低要求，是输入–输出对应关系真实存在、关键变量在场、分布与目标一致——这正是下一章的起点。

2. **复杂体系的表示维度不足**：聚合物的链长/序列/构象、纳米粒子的批次差异，目前人类的观察标准本身就不够准确——需要补充哪些观察维度、建立什么标准，才能让这些对象变成"可计算的数据"？
3. **逻辑关系的先天与后天**：训练数据所需的逻辑关系，多少必须先天具备、多少可以事后整理？目前的初步共识是至少要有输入–输出对应、框架性逻辑可后天赋予——下一章从特征与标签出发继续；
4. **个人或小课题组如何自建文献数据库**：日常结构化积累与集中突击两条路线如何配合？AI 辅助提取（RAG 检索 + 大模型初筛 + 人工核实）的流程如何标准化、幻觉如何系统性地核验？
5. **负面数据的留存**：发表偏倚是文献数据的系统性缺陷——自己的实验记录能否从现在开始记录阴性结果与失败条件？FAIR 数据管理在化学实验室如何落地？
6. **数据量与问题空间的差距**：化学问题空间巨大、造样本成本高，数据量与模型复杂度如何匹配？高通量筛选、自动化实验室在什么条件下值得投入？

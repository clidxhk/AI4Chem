# AGENTS.md — 手册编写规范

本文件是 `手册/` 子目录的专属说明，适用于在本目录下创建、修改讲义章节的所有协作者（包括 AI 编程助手）。仓库整体说明见根目录 `AGENTS.md`。

## 一、手册是做什么的

《AI for Chem 实用学习手册》是共学班的最终交付物：把 12 次讨论的录音转写、成员笔记和对比分析，逐步整理成结构清晰、面向化学研究者的入门讲义。

第一、二次讨论已分别整理为第一、二部分（各含课程版 + 通用版），后续每次讨论对应新增一个部分。

## 二、章节文件组织

- **文件命名**：`第<N>部分-<主题>-<版本>.md`，如 `第一部分-AI-for-Chem的第一次讨论-通用版.md`；
- 每个部分维护**两个版本**：
  - **课程版**（`*-课程版.md`）：保留课题组内部背景与成员发言语境，供组内使用；
  - **通用版**（`*-通用版.md`）：弱化具体课题组背景、成员发言匿名化、口语适度书面化（不改变原意），适合对外发布；
- 两版内容同源：课程版先行整理，通用版在其基础上匿名化改写；
- 配图如需要，存放于本章同目录下的 `图片/` 子目录。

## 三、编写规范

1. **匿名化**：通用版中涉及个人身份的信息一律匿名处理；引文需注明为匿名摘录；
2. **忠实原意**：整理转写内容时可修正口语和转写错误、调整结构，但不得改变发言者的原意；
3. **章节结构**：开篇说明本章来源与整理方式（引言块），正文按问题/主题分节编号（如 1.1、1.1.1），结尾可附讨论沉淀的共识或待探讨问题（自第二部分起的具体结构与文风规范见第四节）；
4. **写作语言**：正文使用中文；专业术语、工具名保留英文原文；
5. **格式**：Markdown；
6. **原始材料不动**：录音转写、成员笔记等一手材料存放在 `第一次/`、`第二次/` 等活动目录，本目录只存放整理成果，不修改原始材料。

## 四、结构与文风规范（自第二部分起生效）

以下规范由第二部分的整理与迭代沉淀而来，后续各部分整理时直接遵循，不必重新摸索。

### 4.1 内容归位，不设"延伸"附录

- 自由讨论的延伸问题与组内补充学习材料**不单独设章**，按主题并入五问正文对应小节（第二部分的归位示例：晶体管开关→发展史；算力计算→硬件；指令集与汇编→编程语言；要不要装 Linux→操作系统；分子表示、AI 与量化计算、学科适配→本质）；
- 趣闻故事（第一个 Bug 是飞蛾、Linux 的诞生、Ariane 5 火箭爆炸等）**织入正文最相关的位置**——Bug 放人物史（霍珀）附近，Linux 诞生放 Win/Linux 对比之后，Ariane 5 放"换台电脑跑不了/可复现"处——作为叙事的一部分，不当花边附录；
- 同一知识点在发言与补充材料中重复出现时只讲一遍；
- 新增内容若有值得进小结的结论，并入原有小结条目或适当加一条（第二部分小结即由四条扩为五条），不要为它单开小节。

### 4.2 通用版文风

- 面向读者、讲义口吻（参照第一部分通用版与第二部分终稿），避免"会议纪要感"：不用"对应 2.6.1 的问题"这类内部交叉引用，少堆纯罗列，多衔接性散文；
- 引文统一标"匿名摘录"；**观点对比处按发言顺序用匿名编号（A、B、C…）标注各成员立场**（第二部分 2.5.3 的现行做法，来自组织者的手动修订）；
- 匿名不等于磨平差异：区分"共识"与"个人独有见解"，独有见解必须保留——课程版署名，通用版用匿名编号（如"自指性""表示化学 ≠ 理解化学""会输出机理图不代表机理已被证实"这类观点）。

### 4.3 整理原则

- 转写错误修正但保留原意（香浓→香农、乔布斯基→乔姆斯基）；查证类或有争议的表述标注不确定性，不写成定论；
- 成员的新见解与关于 AI for Chem 发展方向的讨论是重点保留对象（组织者多次强调）；
- 讨论中的方向性判断进入"待探讨问题"留痕；**下一次整理先检查上一部分的待探讨问题是否被接上**，形成跨章节线索；
- 课程版中的"会后安排"要与会后实际情况对齐（如第二次会后议题最终调整为"数据与信息"），必要时加注说明；
- 引言块保留"AI 参与说明"与状态标注（初稿，供成员核对）。

## 五、与 AI 助手的协作流程（第二部分整理的迭代记录）

第二部分由 AI 助手（ZCode）通读全部一手材料后起草，与组织者经三轮迭代定型。过程记录如下，供后续章节参照：

1. **v1 初稿**：沿用第一部分体例，采用"五问正文 + 自由讨论延伸（2.6）+ 补充学习材料（2.7）"三段式结构；
2. **第一轮反馈**（"通用版有点生硬"）：通用版整体重写为讲义口吻，去会议纪要感，课程版不动；
3. **第二轮反馈**（延伸问题与补充材料并入正文、飞蛾 Bug / Linux 诞生 / Ariane 5 三则趣事融入正文）：两版同步重排，取消 2.6/2.7 附录，内容按主题归位，小结扩为五条；
4. **组织者手动修订**：将通用版 2.5.3 的观点对比改回匿名编号（A–E）标注，该偏好已写入 4.2。

由此形成的工作约定：

- 初稿完成后组织者会通读并给出方向性反馈（文风、结构类），AI 按反馈做**整体迭代**，而非零碎修补；
- **组织者会直接手动编辑手册文件**：AI 覆盖写入前必须先重新读取目标文件、比对差异，保留组织者的手动改动（第二部分重构时即靠先读后写保住了 A–E 标注）；
- 重排与润色不得丢失事实与数据（算力数字、显存带宽、A100 计算过程、Ariane 5 细节等）；
- 每轮修改后按 Git 规范提交并推送，提交信息概括本轮"改了什么、为什么"。

## 六、Git 工作流（强制）

遵循仓库根目录 `AGENTS.md` 的 Git 强制要求：**每次修改后必须 `git add` → 中文提交信息 `git commit` → `git push origin master`**，不允许改动长时间留在本地。
